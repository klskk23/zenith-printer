# 让别的系统用上这台打印机

这份文档是给**对接方**看的。第一个对接方是 nexus-assets 资产台账，下面直接按它来写。

**只想知道怎么接上、不关心为什么**：看 [`nexus-assets.md`](nexus-assets.md)，五分钟能读完。
这一份讲的是每个决定背后的理由，以及照着做会遇到的边界。

Zenith 提供两条方向相反的路，彼此独立，用哪条取决于谁掌握时机：

| | 谁发起 | 用在什么时候 |
|---|---|---|
| **拉** —— 台账数据源 | Zenith | 有人站在机器前面挑要打哪几台设备 |
| **推** —— 打印预设 | 台账 | 台账自己知道什么时候该出纸 |

两条路共用同一个数据形状,先说它。

---

## 一、行信封

两条路都收发同一个 JSON 形状。

```json
{
  "columns": ["id", "序列号", "型号", "入库日期"],
  "rows": [
    { "id": "f3ee54e2", "序列号": "112394521950", "型号": "X100", "入库日期": "2026-08-31" }
  ],
  "total": 30,
  "offset": 0,
  "limit": 1000,
  "generated_at": "2026-09-01T12:00:00Z"
}
```

### 三条硬规矩

**所有值都是字符串。** 这边不做任何类型推断,也不做任何转换。

这不是偷懒。列里装的是要印到纸上的东西,一旦这边猜 `08` 是数字八,某张条码就少了一个
前导零,扫出来是另一件商品;一旦这边猜 `2026-08-31` 是日期,它就会带上一个时区,而印在
标签上的日期可能因此差一天。日期怎么读、布尔值叫什么,是**你**的决定,因为只有你知道这
张标签是给谁看的、用什么语言。

**`columns` 有序且权威。** 它是列的顺序;每一行的键集合必须与它**完全一致**,不多一个,
也不少一个。

少一个键会变成标签上的一处空白,而空白标签不是任何人在纸用完之前会发现的东西。多一个键
则说明两边对这张表是什么没有共识,与其猜,不如现在就说不。

**一次响应里的行是同构的。** 一次只给一个种类的东西。

### 可选的三个字段

`total` / `offset` / `limit` 只在**拉**的时候有意义,用来分页。**推**的时候可以不给,
不给就按 `rows.length` 算。

`generated_at` 目前只是给人看的。

### 列名

任意合法标识符,**中文可以**,唯一的禁忌是不能含 `}`——因为设计里是用 `${列名}` 引用它
的,`}` 会把引用提前闭合。

列名的前缀对这边**没有任何含义**。你想给列加 `sys_` 之类的命名空间是你的事,这边不会为
它做任何特殊处理。

## 二、拉:台账数据源

Zenith 按需或定期来台账取一个类别的设备，存在本机，然后有人在界面上挑要打哪几台。

### 部署方要配的两个环境变量

```
NEXUS_ASSETS_SERVICE_URL=http://127.0.0.1:8080
NEXUS_ASSETS_SERVICE_API_KEY=nxk_xxxxxxxxxxxx.yyyyyyyy
```

**两个都没配时，界面上「从资产台账接入」这个入口整个不出现**——和没配 Google 时一样。只配了
一个也不出现，并在启动日志里说明:一个会出现然后在第一次点击时 401 的按钮，比没有按钮更糟。

它们只从环境变量读,**不落库**。存进数据源就会和 env 里那份漂移——换地址或轮换密钥之后,环境
说一套、十个数据源说另一套,而唯一的症状是刷新莫名开始失败。这也是 Zenith 自己没有认证却仍
然安全持有你的密钥的原因:它压根不接收,也不回显。

### 使用者要做的事:选一个类别

就这一件。Zenith 会调:

```
GET {NEXUS}/api/categories
Authorization: Bearer {key}
Accept-Language: zh-CN
```

用返回的 `path`（`/祖先id/…/自身id/`）在下拉框里做缩进。选中之后先取一行看看列名,让人知道
设计里能写哪些 `${变量}`,再点接入。

刷新时调:

```
GET {NEXUS}/api/rows?category_id=<id>&include_descendants=true&offset=0&limit=1000
```

`total > rows.length` 时按 `offset` 继续拉,上限一万行——超了会在**取之前**就按你报的 `total`
拒绝,不会先把十万行读进内存再说。

### `sys_id` 是行的身份，而且不是一个选项

Zenith 原本用**位置**作为一行的身份:主键是 `(数据源, 行号)`,每次写入都是整表删掉再重排。

这对「人手改表、改完自己刷新、当场就打」成立——改表的人正看着它。对**天天在变的台账**不成立:

> 有人勾了第 2、5、9 行,去接了杯水。这期间台账入库了一台新设备,排在前面。现在第 2 行是原来
> 的第 1 行,第 5 行是原来的第 4 行。他回来点了打印。
>
> **没有任何东西会报错**,因为第 2、5、9 行都还存在。打出来是另外三张标签。

所以刷新按 `sys_id` 合并:同 id 更新、新 id 追加、台账那边删掉的删除,**存活的行留在原位**,
新设备接在末尾。界面上的勾选也按 `sys_id` 走,**刷新之后选择不会被清空**;勾中的 id 真的不在
了,提交时会拒绝并列出是哪几个。

`sys_id` 是写死的,不问使用者。让人选,等于给人一个机会选到一个不稳定的列,而那个故障是无声的。

台账这边要保证:**`sys_id` 非空且唯一**。重复了 Zenith 会拒绝整次刷新并列出每一个重复值;为空
也会拒绝,因为丢掉那一行等于丢掉没人想丢的数据。

### 什么时候刷新

- 默认**只在有人点刷新时**。
- `refreshIntervalSeconds > 0` 时,打开设计页或打印页若已超期就刷一次。
- `refreshBeforePrint` 打开时,提交作业前先刷一次。

**刷新失败从不覆盖已有的行,也不挡住页面。** 台账宕了,这台机器照样能用上一次取到的数据打印,
界面上会写明数据有多旧、以及这次刷新失败了。唯一的例外是 `refreshBeforePrint`:那种情况下取不
到会返回 409 而**不是**用旧数据默默打印——因为拿不到今天的数据就去印昨天的,正是打开那个开关想
避免的事。

### 失败长什么样

都是这个形状,`what` 可以直接摆给人看:

```json
{
  "code": "NEXUS_UNAUTHORISED",
  "what": "资产台账不认这台机器的密钥",
  "why": "它回了 401——多半是这个服务启动之后密钥被轮换或吊销了",
  "next": "请部署这个服务的人更新 NEXUS_ASSETS_SERVICE_API_KEY 后重启。已经取到的行没有变化，仍然可以打印"
}
```

| code | 什么情况 |
|---|---|
| `NEXUS_NOT_CONFIGURED` | 两个环境变量没配全 |
| `NEXUS_UNAUTHORISED` | 台账回了 **401**,密钥不对 |
| `NEXUS_BAD_REQUEST` | 台账回了 **422**,没带 `category_id`——这是 Zenith 的 bug |
| `NEXUS_UNREACHABLE` | 连不上,或超过 30 秒没答完 |
| `NEXUS_BAD_SHAPE` | 回来的不是行信封,`details.detail` 说明是哪一行的哪个键不对 |
| `NEXUS_DUPLICATE_KEY` | `sys_id` 重复,`details.duplicates` 列出每一个 |
| `NEXUS_MISSING_KEY` | 有行的 `sys_id` 为空,或者不再发这一列了 |

401 和 422 是分开的,因为它们是**不同的人**要做**不同的修复**。

列的变化和 Google 表格那条路一致:**新增字段**直接接受;**删掉字段**是破坏性的,需要带
`confirmColumnChange: true` 再来一次。唯独 `sys_id` 消失**不可确认**——确认列变更是同意少一个
列,不是同意退回按位置认行。

## 三、推:打印预设

你的系统把数据交过来,这边直接出纸。

### 预设是什么

「哪个设计、哪台打印机、哪套打印参数、每行打几份」的一个具名组合,有一个稳定的 id。

它存在的理由是:**这四件事都不该由你知道**。它们属于站在机器前面的人,而且会随着换机
器、改设计而变。你只拿一个 id,这四件事在这边随时改,你不用重新发布任何东西。

在**打印预设**页建一个,把 id 抄给台账——台账每个类别存一个预设 id,使用者在台账里**按名字**
从下拉框选。所以名字要是人话;id 不必好看,没人读它。

```
GET /api/print-presets
→ { "presets": [ { "id": "b7b7b0be-…", "name": "路由器标签" } ] }
```

`presets` 这个信封是契约的一部分,不是实现细节:台账直接拿 `presets[].name` 填下拉框。

### 打印

```bash
curl -X POST http://<主机>:3000/api/print-presets/<预设id>/print \
  -H 'Idempotency-Key: <这批活的唯一标识>' \
  -H 'Content-Type: application/json' \
  -d '{
        "columns": ["序列号", "型号"],
        "rows": [
          { "序列号": "112394521950", "型号": "X100" },
          { "序列号": "112394521951", "型号": "X100" }
        ]
      }'
```

```json
202
{
  "jobId": "40d56187-…",
  "status": "queued",
  "requestedCopies": 2,
  "seqClaims": [],
  "deduplicated": false,
  "overflowWarnings": []
}
```

拿 `jobId` 去轮询:

```bash
curl http://<主机>:3000/api/print-jobs/<jobId>
```

这和界面上提交的作业是**同一套状态**,没有为这条路另造一套。

### 请务必带 `Idempotency-Key`

同一个 key 重投拿回同一个 `jobId`,`deduplicated` 为 `true`,**不会多打一批**。

标签纸是实物,打出去收不回来。网络抖动、超时重试、用户双击——这些都会发生,而这个头是唯
一能挡住它们的东西。用「这批活」的自然标识(工单号、批次号)做 key,不要用时间戳。

### 几件要写进你对接文档的事

**行是一次性的。** 不落库成数据源,也不改动任何设计与数据源的绑定关系。交过来的是一批
活,不是一张从此要有人维护的表。

**变量对不上会 422,并且告诉你缺什么:**

```json
{
  "code": "VARIABLE_NOT_DEFINED",
  "details": { "references": ["batch"] }
}
```

意思是这个模板要一个叫 `batch` 的东西,而你这批数据里没有这一列。直接把这句话摆给人看
就行。

**序号池照常发号。** 模板如果引用了序号池,这边会正常发号,并在 `seqClaims` 里把号段完
整返回:

```json
"seqClaims": [{ "variableName": "sn", "start": 1201, "end": 1230, "digits": 6 }]
```

**号是在这边发的。** 不把它读回去,你那边就会另起一套编号,两套各走各的,最后没人说得清
某一张标签上的号是谁发的。

**其他拒绝:**

| code | 什么情况 |
|---|---|
| `BATCH_TOO_LARGE` | 行数 × 份数 > 1000。**不会自动拆**——一个意图变成两个作业,就是两件要对账的事,怎么分该你决定 |
| `QUEUE_PAUSED` | 那台打印机的队列被人暂停了(409) |
| `VALIDATION_FAILED` | 打印机还没探测过,没人知道它的头有多宽 |
| `NOT_FOUND` | 预设、或者它指向的设计/打印机不在了 |

## 四、没有认证

Zenith **没有任何认证**,这是刻意的:它跑在局域网里,给一小撮人和几台打印机用,加一套认
证的代价大于它挡住的东西。

这意味着两件事:

1. **只把它暴露在局域网或 VPN 里。** 任何能访问到端口的人都能打印。
2. **你的凭证在这边是被保护的**(存下不回显),但保护它的是网络边界,不是这个服务。

如果你的部署需要认证,那属于放一层反向代理的事,不是改这个服务的事。
