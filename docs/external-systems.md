# 让别的系统用上这台打印机

这份文档是给**对接方**看的：你有一套系统，里面有数据，你想让它变成标签。

Zenith 提供两条方向相反的路，彼此独立，用哪条取决于谁掌握时机：

| | 谁发起 | 用在什么时候 |
|---|---|---|
| **拉** —— HTTP 数据源 | Zenith | 有人站在机器前面挑要打哪几行 |
| **推** —— 打印预设 | 你的系统 | 你的系统自己知道什么时候该出纸 |

两条路共用同一个数据形状,先说它。

---

## 一、行信封

两条路都收发同一个 JSON 形状。

```json
{
  "columns": ["id", "序列号", "型号", "入库日期"],
  "rows": [
    { "id": "f3ee54e2", "序列号": "112394521950", "型号": "X100", "入库日期": "2026-08-31" }
  ],
  "total": 30,
  "offset": 0,
  "limit": 1000,
  "generated_at": "2026-09-01T12:00:00Z"
}
```

### 三条硬规矩

**所有值都是字符串。** 这边不做任何类型推断,也不做任何转换。

这不是偷懒。列里装的是要印到纸上的东西,一旦这边猜 `08` 是数字八,某张条码就少了一个
前导零,扫出来是另一件商品;一旦这边猜 `2026-08-31` 是日期,它就会带上一个时区,而印在
标签上的日期可能因此差一天。日期怎么读、布尔值叫什么,是**你**的决定,因为只有你知道这
张标签是给谁看的、用什么语言。

**`columns` 有序且权威。** 它是列的顺序;每一行的键集合必须与它**完全一致**,不多一个,
也不少一个。

少一个键会变成标签上的一处空白,而空白标签不是任何人在纸用完之前会发现的东西。多一个键
则说明两边对这张表是什么没有共识,与其猜,不如现在就说不。

**一次响应里的行是同构的。** 一次只给一个种类的东西。

### 可选的三个字段

`total` / `offset` / `limit` 只在**拉**的时候有意义,用来分页。**推**的时候可以不给,
不给就按 `rows.length` 算。

`generated_at` 目前只是给人看的。

### 列名

任意合法标识符,**中文可以**,唯一的禁忌是不能含 `}`——因为设计里是用 `${列名}` 引用它
的,`}` 会把引用提前闭合。

列名的前缀对这边**没有任何含义**。你想给列加 `sys_` 之类的命名空间是你的事,这边不会为
它做任何特殊处理。

---

## 二、拉:HTTP 数据源

Zenith 定期或按需来你这里取行,存在本机,然后有人在界面上挑要打哪几行。

### 你要提供什么

一个 GET 端点,回上面那个信封。

- 如果 `total > rows.length`,Zenith 会带着 `offset` 再来要下一页,直到取满 `total`。
  它**只加 `offset`**,页大小由你决定并在 `limit` 里报回来。
- 配置的 URL 原样使用,你自己的查询参数(过滤、分类)会被保留。
- 上限一万行。超了这边会在**取之前**就按你报的 `total` 拒绝,不会先把十万行读进内存
  再说。

### 建一个

```bash
curl -X POST http://<主机>:3000/api/data-sources/http \
  -H 'Content-Type: application/json' \
  -d '{
        "name": "路由器",
        "url": "http://你的主机:8080/api/rows?category_id=7",
        "keyColumn": "id",
        "headers": { "Authorization": "Bearer …" }
      }'
```

建完是**空的**——建表和取数是两回事,你的系统那天正好没起来,不该导致这张表建不成。
接着刷一次:

```bash
curl -X POST http://<主机>:3000/api/data-sources/<id>/refresh -d '{}' \
  -H 'Content-Type: application/json'
# → {"outcome":"applied","rowsAfter":30,"added":30,"updated":0,"removed":0}
```

### `keyColumn` 是必填的,这里解释为什么

Zenith 原本用**位置**作为一行的身份:行的主键是 `(数据源, 行号)`,每一次写入都是整表删
掉再按顺序重排。

这对「人手改表、改完自己刷新、当场就打」是成立的——改表的人正看着它。对**会自己变的表**
不成立:

> 有人勾了第 2、5、9 行,去接了杯水。这期间你的系统在最前面插了一行。现在第 2 行是原来
> 的第 1 行,第 5 行是原来的第 4 行。他回来点了打印。
>
> **没有任何东西会报错**,因为第 2、5、9 行都还存在。打出来是另外三张标签。

所以 http 数据源必须指定一列作为 key。有了它:

- 刷新按 key 合并:同 key 更新、新 key 追加、你那边消失的删除;
- **存活的行留在原位**,新行接在末尾——不采用你的顺序,因为顺序在这里只是给人用眼睛找行
  用的,决定打什么的是 key;
- 界面上的勾选也按 key 走,所以**刷新之后选择不会被清空**;
- 勾中的 key 如果真的不在了,提交时会拒绝并列出是哪几个——到这里,「这行没了」才真的意味
  着这行没了。

key 值必须**非空且唯一**。重复了会拒绝整次刷新并列出每一个重复值(一次修一个再重取,是
个很慢的办法去发现原来有九个);为空也会拒绝,因为丢掉那一行等于丢掉没人想丢的数据。

### 凭证

`headers` 里的东西**存下之后再也不会被读出来**。`GET /api/data-sources` 只回键名,不
回值。

理由:**Zenith 自己没有认证**(这是刻意的取舍,见 README)。一个没有认证的服务,不能把去
别处认证的钥匙吐回来。

改配置时不传 `headers` 就是「别动它」——你读不回来,要求你重发一遍等于要求你知道它。

### 什么时候刷新

- 默认**只在有人点刷新时**。
- `refreshIntervalSeconds > 0` 时,打开设计页或打印页若已超期就刷一次。
- `refreshBeforePrint` 打开时,提交作业前先刷一次;**只有配了 key 列才允许打开**。

**刷新失败从不覆盖已有的行。** 你的系统宕了,这台机器照样能用上一次取到的数据打印,界面
上会写明数据有多旧、以及这次刷新失败了。唯一的例外是 `refreshBeforePrint`:那种情况下取
不到会返回 409 而**不是**用旧数据默默打印——因为拿不到今天的数据就去印昨天的,正是打开
那个开关想避免的事。

### 失败长什么样

都是这个形状,`what` 可以直接摆给人看:

```json
{
  "code": "HTTP_SOURCE_BAD_STATUS",
  "what": "来源系统拒绝了这次请求",
  "why": "它回的是一个错误状态而不是数据——常见的是凭证已失效,或者地址已经不在了",
  "next": "检查这个数据源的地址与请求头。已经取到的行没有变化,仍然可以打印",
  "details": { "status": 401 }
}
```

| code | 什么情况 |
|---|---|
| `HTTP_SOURCE_UNREACHABLE` | 连不上,或超过 30 秒没答完 |
| `HTTP_SOURCE_BAD_STATUS` | 回了非 2xx,`details.status` 是几 |
| `HTTP_SOURCE_BAD_SHAPE` | 不是行信封,`details.detail` 说明是哪一行的哪个键不对 |
| `HTTP_SOURCE_DUPLICATE_KEY` | key 重复,`details.duplicates` 列出每一个 |
| `HTTP_SOURCE_MISSING_KEY` | 有行的 key 为空,或者你不再发 key 列了 |

列的变化和 Google 表格那条路一致:**新增列**直接接受;**删掉列**是破坏性的,需要带
`confirmColumnChange: true` 再来一次。唯独 key 列消失**不可确认**——确认列变更是同意少
一个列,不是同意退回按位置认行。

## 三、推:打印预设

你的系统把数据交过来,这边直接出纸。

### 预设是什么

「哪个设计、哪台打印机、哪套打印参数、每行打几份」的一个具名组合,有一个稳定的 id。

它存在的理由是:**这四件事都不该由你知道**。它们属于站在机器前面的人,而且会随着换机
器、改设计而变。你只拿一个 id,这四件事在这边随时改,你不用重新发布任何东西。

在**打印预设**页建一个,把 id 抄给你的系统。

### 打印

```bash
curl -X POST http://<主机>:3000/api/print-presets/<预设id>/print \
  -H 'Idempotency-Key: <这批活的唯一标识>' \
  -H 'Content-Type: application/json' \
  -d '{
        "columns": ["序列号", "型号"],
        "rows": [
          { "序列号": "112394521950", "型号": "X100" },
          { "序列号": "112394521951", "型号": "X100" }
        ]
      }'
```

```json
202
{
  "jobId": "40d56187-…",
  "status": "queued",
  "requestedCopies": 2,
  "seqClaims": [],
  "deduplicated": false,
  "overflowWarnings": []
}
```

拿 `jobId` 去轮询:

```bash
curl http://<主机>:3000/api/print-jobs/<jobId>
```

这和界面上提交的作业是**同一套状态**,没有为这条路另造一套。

### 请务必带 `Idempotency-Key`

同一个 key 重投拿回同一个 `jobId`,`deduplicated` 为 `true`,**不会多打一批**。

标签纸是实物,打出去收不回来。网络抖动、超时重试、用户双击——这些都会发生,而这个头是唯
一能挡住它们的东西。用「这批活」的自然标识(工单号、批次号)做 key,不要用时间戳。

### 几件要写进你对接文档的事

**行是一次性的。** 不落库成数据源,也不改动任何设计与数据源的绑定关系。交过来的是一批
活,不是一张从此要有人维护的表。

**变量对不上会 422,并且告诉你缺什么:**

```json
{
  "code": "VARIABLE_NOT_DEFINED",
  "details": { "references": ["batch"] }
}
```

意思是这个模板要一个叫 `batch` 的东西,而你这批数据里没有这一列。直接把这句话摆给人看
就行。

**序号池照常发号。** 模板如果引用了序号池,这边会正常发号,并在 `seqClaims` 里把号段完
整返回:

```json
"seqClaims": [{ "variableName": "sn", "start": 1201, "end": 1230, "digits": 6 }]
```

**号是在这边发的。** 不把它读回去,你那边就会另起一套编号,两套各走各的,最后没人说得清
某一张标签上的号是谁发的。

**其他拒绝:**

| code | 什么情况 |
|---|---|
| `BATCH_TOO_LARGE` | 行数 × 份数 > 1000。**不会自动拆**——一个意图变成两个作业,就是两件要对账的事,怎么分该你决定 |
| `QUEUE_PAUSED` | 那台打印机的队列被人暂停了(409) |
| `VALIDATION_FAILED` | 打印机还没探测过,没人知道它的头有多宽 |
| `NOT_FOUND` | 预设、或者它指向的设计/打印机不在了 |

---

## 四、没有认证

Zenith **没有任何认证**,这是刻意的:它跑在局域网里,给一小撮人和几台打印机用,加一套认
证的代价大于它挡住的东西。

这意味着两件事:

1. **只把它暴露在局域网或 VPN 里。** 任何能访问到端口的人都能打印。
2. **你的凭证在这边是被保护的**(存下不回显),但保护它的是网络边界,不是这个服务。

如果你的部署需要认证,那属于放一层反向代理的事,不是改这个服务的事。
