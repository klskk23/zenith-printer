# Zenith Printer

在浏览器里设计标签，用桌上那台标签机打出来。局域网内一个容器跑完——不上云、不用注册、
不需要反向代理。

**[English →](../README.md)**

- **浏览器里的编辑器**：SVG 画布，文字、条码、二维码、图片，标尺、吸附、撤销。
- **可变字段与数据源**：手工填、从序号池取、上传 CSV，或者链接一张 Google 表格，想刷新
  的时候再刷新。
- **两类打印机**：精臣走 USB 串口，霍尼韦尔走 ZPL over TCP 9100。
- **渲染确定性**：字体随镜像走并且关掉了系统字体，同一个模板在任何机器上打出来一模一样。
- **amd64 与 arm64 通吃**：一个 tag 同时服务两者，树莓派和机架服务器拉的是同一个名字。

## 快速开始

```bash
curl -O https://raw.githubusercontent.com/klskk23/zenith-printer/main/deploy/docker-compose.yml
docker compose up -d
```

然后在同一网段的任意机器上打开 `http://<主机地址>:3000`。

数据（数据库和上传的图片）落在 compose 文件旁边的 `./data`。换机器就是 `rsync -a data/`，
没有第二步。

> 首次拉取如果提示未授权，是 GitHub Packages 默认私有：去仓库的 Packages 页面把
> `zenith-printer` 改成 public，或者先 `docker login ghcr.io`。

## 跑之前要知道的两件事

**容器是 privileged 的，并且把宿主机的 `/dev` 挂了进去。** 精臣打印机是随插随拔的 USB
CDC 设备，只给 privileged 不够：Docker 给特权容器的 `/dev` 是一份 **tmpfs**，即容器启动
那一刻的设备节点快照，之后插上的打印机永远不会出现。两条设置都在 compose 文件里，理由就
写在旁边。

**没有鉴权。** 能连到 3000 端口的人都能打标签，也能取消别人的任务。这是「桌边工具」这个
定位下有意的取舍——请把它留在局域网或 VPN 里，别放到能通外网的地方。

## 日常用法

### 打印一张标签

1. 打印机页面添加设备（精臣填 `/dev/ttyACM0`，霍尼韦尔填 `IP:9100`），点**探测**读出
   型号和分辨率——没探测过的打印机不能打印，因为没人知道纸多宽。
2. 标签设计页画好，保存成模板。
3. 点打印，确认份数和行数。

### 让标签内容来自表格

数据源页有三种来源：

| | |
|---|---|
| **上传 CSV** | 内容存在本机，可以直接在表格里改 |
| **链接 Google 表格** | 需要部署方配好服务账号，见 [`deploy/README.md`](../deploy/README.md) |
| **从资产台账接入** | 选一个类别就行，见下 |

后两种在本机只读——内容改动回源头那边做，这边点刷新。改了也没用：下一次刷新会把它覆盖掉，
而且不会告诉你。

设计里用 `${列名}` 引用某一列。打印时选行、选正序倒序、翻页勾选。

### 从资产台账接入一个类别

部署方在环境变量里配好这两项之后，数据源页会多出「从资产台账接入」：

```
NEXUS_ASSETS_SERVICE_URL=http://127.0.0.1:8080
NEXUS_ASSETS_SERVICE_API_KEY=nxk_xxxxxxxxxxxx.yyyyyyyy
```

**没配就不出现**——和没配 Google 时一样。一个按不动的按钮比没有按钮更糟，因为唯一的发现方式
是去按它。

接入时**只选一个类别**。地址、密钥、用哪一列认行，一样都不问：

- 前两样是部署决定，从环境变量读。存进数据源就会和 env 里的那份**漂移**——换台账地址或轮换
  密钥之后，环境说一套、十个数据源说另一套，而唯一的症状是刷新莫名开始失败。
- 第三样是台账自己的答案:`sys_id`，设备的 UUID。让人选，等于给人一个机会选到一个不稳定的
  列，而那个故障是无声的。

选中类别后会先显示它有哪些列，这样你在建数据源之前就知道设计里能写哪些 `${变量}`。

**刷新按 `sys_id` 合并**:同 id 更新、新 id 追加、台账那边删掉的删除，**存活的行留在原位**。
这是台账数据源能安全存在的前提——台账的行天天在变，而这个产品原本用**位置**作为行的身份:

> 有人勾了第 2、5、9 行，去接了杯水。这期间台账入库了一台新设备，排在前面。现在第 2 行是原来
> 的第 1 行。他回来点了打印。
>
> **没有任何东西会报错**，因为第 2、5、9 行都还在。打出来是另外三张标签。

勾选也按 `sys_id` 走，所以**刷新之后选择不会被清空**；勾中的设备如果真的不在了，提交时会拒绝
并说出是哪几个。

数据源可以设**自动刷新间隔**（默认 0，即只在你点刷新时刷）和**打印前先刷新**（默认关）。刷新
失败一律不覆盖已有的行、也不挡住页面——台账宕了，这台机器照样能打印；唯一例外是「打印前刷新」，
那种情况下取不到会返回 409 而不是拿旧数据默默打印。

### 让别的系统直接来打印

反过来的方向：外部系统把数据交过来，这边直接出纸。

在**打印预设**页建一个预设——它是「哪个设计、哪台打印机、哪套参数、打几份」的具名组合
——然后把它的 id 交给对方。对方只需要：

```bash
curl -X POST http://<主机>:3000/api/print-presets/<预设id>/print \
  -H 'Idempotency-Key: <这批活的唯一标识>' \
  -H 'Content-Type: application/json' \
  -d '{"columns":["序列号"],"rows":[{"序列号":"112394521950"}]}'
# → 202 {"jobId":"…","requestedCopies":1,"seqClaims":[…]}
```

拿 `jobId` 去轮询 `GET /api/print-jobs/<jobId>`，和界面上提交的作业是同一套状态。

几点值得写进对接文档：

- **`Idempotency-Key` 一定要带。** 同一个 key 重投一次拿回同一个 jobId，不会多打一批。
- 交过来的行是**一次性**的，不落库成数据源，也不改动任何设计与数据源的绑定关系。
- 模板要用的变量这批数据里没有时，返回 422，`details.references` 里**列出缺的名字**。
- 模板引用了序号池时照常发号，`seqClaims` 会把号段完整返回——号在这边发，不说清楚就会
  变成两套编号各走各的。
- 预设指向的设计和打印机随时可以在这边换，对面不用改任何东西。

### 清理没人用的图片

粘贴到设计里的图片会立刻上传，被丢弃的粘贴就留在了服务器上。设置页最下方「服务端维护」
里有一个按钮，或者：

```bash
docker compose exec zenith-printer \
  node --experimental-strip-types packages/cli/src/index.ts images-prune --delete
```

只会删掉**没有任何设计引用、且上传超过 24 小时**的图片；还在用的、以及刚粘上去还没保存
的，都不会动。

## 从源码构建

```bash
make            # 看有哪些目标
make doctor     # 看这台机器缺什么
make check      # typecheck + lint + 测试
make image      # 构建部署镜像
make up         # docker compose up -d
```

需要 Node 26（**不能是 26.4 及以后**——那些版本的串口读取会停摆，打印机会表现为「连不上」，
详见 [`deploy/README.md`](../deploy/README.md)）和 npm 12。
