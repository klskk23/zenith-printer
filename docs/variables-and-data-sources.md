# 变量与数据源（设计共识）

本文是一次完整访谈的结论，供 `/speckit.specify` 使用。它记录**决定了什么**、
**否决了什么**、以及**为什么** —— 后两者比第一者更容易在实现中被重新发明。

替换对象：现有的「可变字段」（`variableFields` + `{ $var: name }`）整体废弃。

---

## 1. 变量模型

变量有三种，都在设计里命名和使用：

| 种类 | 取值来源 | 打印时是否询问 |
|---|---|---|
| **设计期常量** | 在编辑器里写死 | 否 |
| **自增** | 序号池 | 否 |
| **数据源** | 表格的某一列 | 否（由所选的行决定） |

### 手工填入被删除

理由：对单个元素而言，「打印时填一个值」不比直接改文本框多任何东西，还多一层
间接。

它唯一没被覆盖的场景是**同一个值出现在多个元素里**（例如 SKU 既印成文字、又编进
二维码的 URL），分两处手改可能不一致 —— 而条码和文字说的不是同一件事，属于
「扫出来是错的、人眼看着是对的」那种故障。**设计期常量正是为此保留的**。

注意最常见的那种重复（条码 + 它自己的可读字符）已由 `showHumanReadable` 覆盖，
不需要变量。

### 数据源列没有命名层

不提供 `收件人 = ${收件人}` 这样的别名。内容里直接写列名。

理由：别名唯一能买到的是「换数据源时只改定义」，而这一点已由「设计绑定一个数据源」
本身提供 —— 换绑改一个下拉框即可。保留别名等于两条路通向同一个地方，而两条路会让
「这两个是不是一回事」在 UI、文档、解析优先级上反复出现。

**修订（2026-08-22）**：本节原本还写着「内容里直接写路径」，指 `${数据源名.列名}`。
路径已取消，见下节。

### 序号池是独立实体

计数器不再挂在模板名下，而是与数据源并列的顶层对象，设计引用它。

两个后果：

- **「未保存的设计不能用序号」这条限制消失。** 那条限制纯粹是实现细节渗到用户
  面前 —— 计数器没有可挂靠的东西。
- **多个模板可以共用一条流水。** 小盒标签与外箱标签用同一个序列号，在旧模型下
  做不到（两个模板各数各的，号会撞）。
- **「重置计数器」成为用户可见的危险操作**，必须确认：重置后会印出与已经贴出去
  的标签重号的序列号。

## 2. 引用文法

内容永远是**普通字符串**。IR 中的 `{ $var: string }` 形态整个消失，随之消失的还有
`isVariableRef`、绑定选择器、以及「这个元素绑没绑」这个概念。

### 形式

```
${名称}                设计期常量、自增变量，或所绑数据源的一列
$${                    转义，输出字面的 ${
```

**单层命名空间。** 三种来源写法相同，因为一个设计只绑一个数据源，写出数据源前缀
不携带任何信息。

**引用必须整个包在一对括号内。** 曾考虑过 `${A}.${B}` 与 `${A}.{B}`，两者都被
否决，因为引用的边界跑到了括号外，后面跟什么字符都可能被吞进来：

```
版本 ${major}.${minor}     ← 两个普通变量，中间一个字面点号
批号 ${lot}.{已校验}        ← 一个变量 + 字面文本
```

**修订（2026-08-22）——取消两级路径 `${数据源名.列名}`。**

原方案要求写出数据源前缀，并为此付出两条文法规则（以第一个 `.` 分路径、引号段
包裹含点号的列名）与一条对用户表格的限制（列名不得含点号）。但一个设计最多绑定
一个数据源，前缀因此恒等于那个数据源 —— 是一段永远算得出、却要求用户每次手写的
冗余。

连带的三处简化：

- 点号在括号内恢复为普通字符，`${单价.含税}` 直接可用，引号形式取消
- 数据源名不再是文法的一部分（见下节的对应修订）
- 「一个设计引用了两个数据源」不再可能表达，`MULTIPLE_DATA_SOURCES` 这个错误码
  随之消失 —— 绑定成了模板上的一个字段，结构上就只能有一个

代价：常量、自增与列共用一个命名空间。重名时**报错**，不定优先级 —— 静默的优先级
规则属于「看起来没问题，直到有人往表里加了一列」那一类缺陷，而加列的人无从知道
自己遮蔽了某个设计的常量。

### 未定义与不完整

必须区分两种状态，否则编辑器会在每敲一个字时闪一次错误（或者白屏 —— 这正是
`ed3cedd` 修掉的那个故障的根源）：

| 状态 | 例子 | 行为 |
|---|---|---|
| **不完整**（没有闭合的 `}`） | `${sk` | 当作字面文本画出，**不报错**。它只是还没写完 |
| **完整但未定义** | `${nope}` | 原样画出，同时报**阻塞性问题**，打印按钮变灰 |

第二条落进既有机制：`inspect()` 产出违规项，`blockingViolations` 禁用打印按钮。
新增 `VARIABLE_NOT_DEFINED`。

画成空白是错的 —— 会让人以为元素坏了。

## 3. 数据源

### 形态

- 一个数据源 = **一张表**：列 + 行。
- 导入 Google Sheets 时**选定一个工作簿**，它成为一个独立数据源。
- 数据源是**全局实体**，与模板无关；模板通过一个 `dataSourceId` 字段绑定其中一个。

### 名字是标签，不是标识符

原本的理由是「`${订单表.收件人}` 里的 `订单表` 是文法的一部分」。**取消两级路径之后
这个理由不成立了** —— 绑定按 id 记录，改名不影响任何引用。

现在的状态：

- **可以随时改名**。改名对引用零影响，没有理由禁止
- **仍然唯一**，但这是可用性约束而非标识约束：两张同名的表在下拉框里无从分辨

**删除也随之松开。** 原方案要在删除时列出受影响的设计并拦住操作。但列引用是裸名，
把设计重新绑到另一张同形状的表就全部复原 —— 一个下拉框的事。既然可恢复，就不该把
删除当成危险操作。确认仍然要求，理由换成「表内的行不可恢复」，与谁在引用它无关。

断掉的设计由**模板列表与设计页上的警告标记**指出，而不是由删除对话框拦住。该状态
读取时计算、不存储 —— 存储的状态会与数据源的实际情况漂移，而漂移的方向恰好是
「显示正常、实则已断」。

**替换时的列消失确认保留**：绑定还在，断的是某一列，确认框能指名道姓说出是哪一列
没了。那是决策当下最有用的信息；删除给不出这种信息，确认框只能说套话。

### 一切皆文本

**不做任何类型推断。** `007` 不能变成 `7`。

零件号、批号、邮编丢前导零是标签领域最经典的数据损坏，而且**印出来才发现**。
同理 `2024-01-05` 不应被日期化，`1E5` 不应变成 `100000`。

需要格式化就在导入前处理好。

### CSV 导入

- **编码探测 + 允许手工指定。** 中文环境里 Excel 导出的 CSV 常是 GBK；按 UTF-8
  直读得到一片乱码，而乱码是「一看就知道错了但不知道怎么办」的故障。
- **表头必需。** 列名就是引用名，没有表头就写不出 `${列名}`。无表头的 CSV 拒绝导入。

### 管理界面

shadcn + TanStack Table。增、删、改、上传 CSV。

## 4. 一个设计只能引用一个数据源

用 guard 强制，引用了第二个就阻塞打印。

理由：打印模型是「一张标签对应一行」。引用两张表时，勾选的是哪张表的行、两张表
的行如何对应，都没有答案。

**跨表关联明确列入不做。** 正确的做法是在数据侧先把表合并好再导入 —— 用 Excel
或 SQL 合并，比在标签软件里造一个半吊子的连接引擎可靠得多。

「按行号对齐两张表」也被否决：两表行数或顺序不同时会**静默印错**。

## 5. 打印任务模型

### 份数 × 行

选 40 行、每行 2 份 = 80 张。份数输入框保留。

**复制品共用同一个自增号。** 份数的语义是「这一张再来一份」，复制品理应一模一样；
需要每张不同号的场景，应当选 80 行或把序号做进行里。

### 快照抄行值

任务快照必须把用到的**行的值抄进去**，而不是记录对表的引用。这是既有原则
（FR-050/051：历史自包含，图片为此做了软删除）逼出来的。

两个代价，都要在界面上认：

- 快照变大。5000 行就是几 MB 一条任务记录。
- **补打会重印当时的数据。** 卡纸补 40 张 —— 正是要的；「地址填错了改完再打」——
  补打**不会**捡起修正，那种情况必须走新任务。

### 打印顺序：表格顺序

无论勾选先后，永远按行号升序。可预测、补打能对上、实物标签顺序与表格一致便于
人工核对。

## 6. 行选择与预览

打印对话框中开一块 field，用 data table 勾选，10 条一页。

### 选择以紧凑式表达

```jsonc
{ "all": true }
{ "ranges": [[1, 200], [350, 400]], "ids": [7, 9] }
```

否决了「传行 id 列表」：5000 行就是几百 KB 的数组，而且「全选」这个**意图**丢失了。
紧凑式还有个附带好处：**X-Y 区间输入**天然就是这个形式。

**必然后果：「全选」在提交那一刻求值。** 勾选到提交之间新增的行会被包含进去。
窗口只有几秒，快照一旦生成即冻结。

### 全选 = 整张表

不是当前页的 10 条。按钮上**必须写明行数**（`全选（5000 行）`），不能是一个光秃秃
的「全选」—— 5000 张标签是几十分钟机器时间和一整卷纸。

### 预览

沿用既有规则：预览**第一张**，即打印顺序上的第一行。批次里的标签本就不同，第一张
是真的会被打出来的那一张，而合成的「代表图」谁也收不到。

## 7. 流式渲染

批量上限从 `MAX_COPIES = 100` 提高，渲染改为流式。

**这不是一个常量的事。** 现在 `buildJobPages` 一次性把所有页渲染成位图数组再交给
驱动：1000 张 400×240 的标签是 12MB 位图同时驻留内存，而且要先渲染 33 秒才发出
第一张。

涉及面：

- **`PrinterDriver.printPages(pages: BinaryBitmap[], ...)` 收的是数组**，需要改成
  迭代器或按序回调 —— 这是宪章约束的驱动端口契约，**四个驱动全部要跟着改**
  （精臣、ZPL、dry-run、以及搁置中的 TSPL）
- `buildJobPages` 改为惰性序列
- 进度上报本来就是按页的，不受影响；失败时 `pagesPrinted` 的语义不变

### 提交前检查必须抽样

`checkBatch` 现在遍历所有份数检查越界，包括**给每一行编一次条码**。5000 行意味着
任务还没开始就先编 5000 次条码。

抽样策略需在规格中写明（前 N 行 + 内容最长的若干行 —— 条码宽度随内容变，最长的
最可能超宽）。**抽样意味着漏报，这是取舍不是实现细节。**

## 8. 迁移

**目前没有生产数据**，因此：

- 对可变字段可以做**破坏性删除**（丢掉 `variable_fields` 表与相关列）
- REST 契约可自由破坏性修改（`manualFieldValues`、`sequenceOverrides`、
  `/templates/:id/print-form` 均将变化）

**但其余数据必须保留**：打印机、打印参数，**尤其是偏移校正值** —— 那是对着实物量
出来的，重做要花时间和标签。

若将来在有数据的环境上迁移，另有一条：既有内容里字面的 `${` 必须转义成 `$${`，
否则会突然变成一个引用。

---

## 9. 明确不做

- 手工填入（打印时询问取值）
- 数据源列的别名层
- 跨数据源关联 / 连接
- 引用路径（含两级 `${源.列}` 与三级 `${文件.工作表.列}`）
- 列的类型推断

---

## 10. 待确认与风险

| 项 | 说明 |
|---|---|
| 抽样策略 | 提交前检查的抽样规则会漏报超宽，需要在规格里把「漏什么」写清楚 |
| 快照体积 | 5000 行任务的快照有几 MB，长期下来 SQLite 会变大。是否需要历史清理策略 |
| 序号池重置 | 危险操作的确认文案需要说清后果（重号），而不是一句「确定吗」 |
| 名称重名 | 常量与列同名时报错。若实践中撞得频繁，再考虑加一种消歧写法 |
| 工程量 | 本文覆盖的范围是一个大 spec；实现顺序建议：流式渲染 → 变量与语法 → 数据源 |
