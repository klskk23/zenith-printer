# Zenith Printer 前端设计稿 v2

本文是 `docs/frontend-design.md` 的完整版，作为后续 `/speckit.specify` 的输入。
所有决策来自 2026-08-20/21 的设计讨论，分支编号 A–I 与讨论过程一一对应。

> 本文只描述**做什么**与**为什么**，不描述实现细节。
> 受 `.specify/memory/constitution.md`（v1.2.0）约束，特别是原则 III（UX 一致性）
> 与原则 IV（语言规范）。

## 0. 决策汇总

| 分支 | 议题 | 结论 |
|---|---|---|
| A | 标签栏模型 | IDE 模型：tab = 已打开的文档，可同时打开多个设计，可关闭 |

## 2. 全局布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ Zenith Printer                                  ● 已连接   [中文 ▾]  │  顶部状态栏
├──────────────────────────────────────────────────────────────────────┤
│ 首页 │ ●标签设计 ×│ 运输标签 ×│ 打印机 ×│                            │  标签栏
├───────────────┬──────────────────────────────────────────────────────┤
│ 首页          │                                                      │
│ 标签设计      │                                                      │
│ 模板库        │                  内容区                              │
│ 打印机        │           （当前激活 tab 的页面）                    │
│ 打印队列   ③  │                                                      │
│ 打印历史      │                                                      │
│ 设置          │                                                      │
└───────────────┴──────────────────────────────────────────────────────┘
   侧边栏
```

### 2.1 顶部状态栏

- 左：产品名。
- 右：**服务端连接状态**（已连接 / 连接中 / 已断开），语言切换。
- 断开时状态点转为警示色，并在内容区顶部显示一条横幅——状态栏那个小圆点
  不足以解释「为什么按钮都没反应」。

### 2.2 标签栏（分支 A）

采用 IDE 模型：**tab 代表一个已打开的文档，不是导航目的地**。

- 侧边栏的 6 个条目**全部**以 tab 形式打开。
- 可同时打开**多个标签设计** tab（例如一张 50×30 和一张 100×60 并行编辑）。
- 每个 tab 可关闭；激活的 tab 以圆点或高亮标示（原稿的 `[x]` 是「当前激活」的意思，
  但 `×` 在通用语汇里是关闭按钮，两者必须用不同符号，否则用户会点错）。
- **未保存的设计** tab 标题旁显示未保存标记（`●`）。
- 关闭带未保存修改的 tab 时确认。
- **刷新页面**：`beforeunload` 提示是否离开；不恢复 tab 集合（见 §2.4）。

### 2.3 侧边栏

- 固定 7 项，顺序如上表。
- 「打印队列」右侧显示进行中 + 排队中的任务数徽标；为 0 时不显示。
- 点击已打开的条目 → 切换到该 tab，不新建。

### 2.4 路由（分支 I，I2）

**URL 反映当前激活的 tab。**

| URL | 含义 |
|---|---|
| `/` | 首页 |
| `/design/new` | 一张未保存的空白设计 |
| `/design/:templateId` | 从某模板打开的设计 |
| `/templates` `/printers` `/queue` `/history` `/settings` | 对应页面 |

- 切换 tab 时更新 URL；刷新后**只恢复 URL 指向的那一个 tab**，其余丢失。
  这与「不恢复 tab 集合」并不矛盾——URL 里本来就只装得下一个。
- `/design/new` 刷新后是一张新的空白画布，原内容丢失（`beforeunload` 已经警告过）。
- 深链可分享：「你打开这个模板看一下」是内部工具的常见需求。
- 服务端的 SPA fallback 已实现，任意路径刷新都能回到应用。

**实现：React Router。**

> **宪章注记**：技术栈由 `.specify/memory/constitution.md` 锁定，
> `react-router-dom` 是本期新增依赖，实现时的 PR 必须说明引入理由
> （与 shadcn/ui 缺失组件时的自建说明同一条规则）。
>
> 需要注意的模型差异：**tab 集合才是真正的视图状态，URL 只是当前激活 tab 的投影**。
> React Router 默认想接管整棵视图树，但这里不能让它决定「哪些 tab 存在」——
> 已打开但未激活的 tab 必须保持挂载，否则切回去时编辑状态就丢了。
> 因此路由只负责「激活哪一个」，tab 内容由 tab 集合渲染并以 CSS 控制显隐。

### 3.1 打印机卡片

显示：在线状态、队列运行/暂停、待处理任务数、**耗材余量**。

**两种机型在余量上天然不对等**，这个差异必须表达出来而不是留空：

- 精臣 B3S_P 能报（`allPaper - usedPaper`）→ 显示具体张数。
- 霍尼韦尔 PC310T 报不了（`~HS` 只说「有没有纸」）→ 显示「本机型无法上报」。

最近 5 条。失败的条目直接给「重新提交」——FR 已规定失败任务需人工重新提交，

## 4. 标签设计（分支 B、C、F、H）

```
┌──────────────────────────────────────────────────────────────────────────┐

├────────────┬─────────────────────────────────────────┬───────────────────┤

├────────────┴─────────────────────────────────────────┴───────────────────┤

└──────────────────────────────────────────────────────────────────────────┘
```

### 4.1 两个入口，同一个编辑器（分支 B）

- **标签设计**：新建空白画布，或从模板打开。可以直接打印而不保存（一次性标签）。
- **模板库**：管理已保存的模板。打开其中一个 → 新建一个「标签设计」tab。

两者共用同一套编辑器组件，不存在「模板编辑器」和「设计编辑器」两份实现。

### 4.2 元素类型（分支 C）

`文本` `条码` `二维码` `图片` `直线` `矩形` `椭圆`

- **去掉原稿的 `Time`**：打印时刻的时间戳属于「可变字段」的一种，
  已有的可变字段机制覆盖了它，单独做一个元素类型会造成两条并行的取值路径。
- **`Shape` 拆成 `矩形` 与 `椭圆`**：矩形即现有 `rect`（支持圆角与填充）；
  椭圆是本期新增的元素类型。

**椭圆（新增）**

与矩形对称，用包围盒描述，不用圆心 + 半径——这样两种形状的属性面板、
选择框、缩放手柄完全一致，正圆只是宽高相等的椭圆，不需要单独的元素类型。

| 属性 | 说明 |
|---|---|
| `xMm` / `yMm` / `widthMm` / `heightMm` | 包围盒 |
| `strokeWidthDots` | 描边宽度，整数 dot |
| `filled` | 填充或描边 |
| `rotation` | 0/90/180/270 |

- 缩放**自由**（与矩形一致）——包围盒形状本身没有固有比例；
  按住 Shift 时锁定等比，用于画正圆。
- 描边同样是**中心描边**，需要按半个描边宽度内缩，使外边缘与声明的包围盒重合
  （与 `renderRect` 现有做法一致）。

### 4.3 标尺与缩放（分支 F）

- **双轴**：水平 + 垂直。原稿只画了上方，但垂直定位同样需要。
- **单位**：主刻度 mm，次刻度按 dot 细分（203 dpi 下 1 mm ≈ 8 dot）。
- **纯展示**（F1）：不提供从标尺拖出参考线的功能。标签版面太小，参考线收益不大。
- **网格吸附**（F3）：拖动元素时吸附到 dot 网格。这有实际意义——
  水平/垂直线不落在整点上会被二值化削掉，渲染层已经做了 snap，
  编辑器让用户直接感受到同一个网格更一致。
- **临时脱离**：按住 Alt 时不吸附。
- **缩放**：「适应窗口」+ 滚轮缩放，不用固定档位。
  标签尺寸跨度大（50 mm 到 104 mm），固定档位不够用。
  50×30 mm 标签在 203 dpi 下只有 400×240 像素，1:1 显示时小到无法精确摆放。
- 标尺刻度**必须跟随缩放**。

### 4.4 编辑交互（分支 H）

| 操作 | 行为 |
|---|---|
| 选中 | 单击元素；点击空白处取消选中 |
| 移动 | 拖拽；吸附到 dot 网格（Alt 临时脱离） |
| **旋转** | **锁死 0° / 90° / 180° / 270°**，拖拽旋转手柄时吸附到最近直角 |
| **缩放** | **等比**，拖拽角手柄 |
| 删除 | 右键菜单 → 删除；或 Delete 键 |
| **图层** | 右键菜单 → 置顶 / 置底；也可在图层面板中操作（§4.5） |

各元素类型的缩放语义：

| 类型 | 缩放行为 |
|---|---|
| 文本 | **只改文本框尺寸，字形不变形**。字号是独立属性，单独调 |
| 条码 | **高度自由；宽度量化吸附**（见 §4.5） |
| 二维码 | 等比 |
| 图片 | 等比 |
| 直线 | 拖两端；线宽以 dot 为单位单独调 |
| 矩形 | 自由改宽高（不等比——矩形本来就没有固有比例） |
| 椭圆 | 自由改宽高；Shift 锁等比画正圆 |

> **实现注记**：`packages/web/src/editor/guards.ts` 的 `boundsOf()` **不考虑旋转**。
> 现在没有旋转 UI 所以看不出来，一旦加上直角旋转，90°/270° 的元素选择框和
> 越界检测都会算错（宽高需要互换）。这是本期必须一并修的。

### 4.5 图层面板

左侧栏的「图层」是一个**元素列表**，自上而下即渲染顺序的倒序
（列表最上 = 最靠前 = `ir.elements` 数组末尾）。

- 每项显示元素类型图标与摘要（文本显示首行内容，条码显示码制与内容）。
- 点击选中，与画布上的选中状态双向同步。
- 提供「置顶 / 置底」两个动作，与右键菜单等价。
- **只做置顶 / 置底，不做任意排序**——这是原始需求里「简单的图层概念」的范围，
  拖拽重排在标签这种元素数量个位数的场景里收益不大。

它存在的意义是在元素重叠时仍能选中被压住的那个——纯靠画布点击做不到这件事。

### 4.6 条码宽度：量化吸附

条码宽度不是连续的：

```
条码宽度 = 模块宽度(dot) × 模块数
```

**模块数由内容和码制共同决定，改不了**。`ABC-12345` 在 Code 128 下就是 123 个模块。
所以宽度只能取模块数的整数倍：

| 模块宽度 | 203 dpi 下 X 尺寸 | `ABC-12345` 总宽 |
|---|---|---|
| 1 dot | 0.125 mm | 15.4 mm |
| 2 dot | 0.25 mm | 30.8 mm |
| 3 dot | 0.375 mm | 46.2 mm |
| 4 dot | 0.5 mm | 61.5 mm |

**下限由扫描枪决定，不是渲染决定的。** Code 128 的 X 尺寸规范下限约 0.19 mm，
实务推荐 0.25 mm。所以 203 dpi 下**模块宽度最小取 2**。

> **实测确认（2026-08-21，B3S_P + 原厂 50×30 纸）**：模块宽度 2 / 3 / 4 dot
> 各打印一张，扫码枪与手机**三张全部可读**。下限 2 dot 成立。

### 二维码的尺寸同样是量化的 ⚠️

这一条在实现阶段才发现，设计稿初版没有预见。

二维码遵循同一条规律：`边长 = 模块宽度 × 模块数`，而模块数由**内容长度与纠错等级
共同决定**——同一段内容，纠错等级 L/M/Q 是 50 个单位，H 变成 58。所以二维码
**不能自由缩放到任意尺寸**，只能取模块数的整数倍。

处理方式与条码一致：元素记录模块宽度，渲染尺寸由它导出，缩放时**向下取整**到
可达尺寸（保证不超出声明尺寸）。

**这条对界面有个直接后果**：元素框不够大时，用户设定的模块宽度会被悄悄改小。
实测时探针元素只有 24 mm，模块数 50，4×50 = 200 dot 装不下，于是静默降为 3——
「比较 2/3/4」的实验打出了两张完全相同的标签。因此**属性面板必须显示实际生效的
模块宽度，而不是用户请求的值**。

交互：

- 拖拽宽度手柄时吸附到最近的可达宽度 `round(目标宽度 / 模块数) × 模块数`，
  下限卡在模块宽度 2。
- 属性面板把**模块宽度**作为主控件（dot 与 mm 同时显示），
  `宽度 mm` 显示为只读的派生值——让用户看得见自己离扫描下限有多近。

**实测结论（推翻早先的假设）**：7 组码制/内容 × 缩放 1/2/3/5/7，
所有条边缘全部落在整数 dot 上，零例外。早先「模块宽度必须是偶数」的结论
源于一次测量失误（用第一条 path 的 stroke-width 去算了所有条的边缘，
而 bwip-js 按条宽分成 4 条 path、各有各的 stroke-width）。
**限制应放宽为任意整数 ≥ 2**，可用宽度档位因此翻倍。

### 4.7 多行文本（分支 H，T1）

**只支持显式换行**，不做按框宽自动折行。

理由：自动折行必须知道每个字符的实际宽度，而**浏览器与 resvg 的字体度量并不完全一致**。
同一段文字、同样的框宽，两边可能在不同的字上折行——编辑器里三行，打出来四行，
最后一行掉到框外。前后端共用同一份 `ir-to-svg` 正是为了排除这类分叉，
自动折行会把它重新引进来。

- 文本内容中的 `\n` 拆成多行；拆行是纯字符串操作，两端必然一致。
- **行距固定 1.2 倍字号**（不做成可调属性，需要时再放开）。
- 属性面板的内容输入框改为多行文本域。

### 4.8 边距的视觉表达（分支 D）

Profile 的四边边距在画布上以**斜纹阴影**绘制。

- **不阻止**在边距内放置元素——边距是建议而非硬约束，用户可能确实想压边。
- 未选择 Profile 时不绘制边距，并在画布角落给出提示，
  否则用户会以为「这个模板没有边距」。

### 4.9 越界与阻断

沿用现有规则：

- **阻断级**问题（如超出打印头宽度）→ 打印按钮禁用，顶部红色说明。
- **警告级**问题（如超出标签边界）→ 画布上标记，不阻断。

## 6. 打印机（分支 D）

在现有页面基础上增加**偏移校正**。

```
┌──────────────────────────────────────────────────────────────────┐
│ B3S_P                                            队列：运行中    │
│ niimbot · /dev/ttyACM0 · B1                                      │
│ 型号 B3S_P   分辨率 203 dpi   最大宽度 104.0 mm (832 dot)        │
│ 密度 1–5     固件 x.y.z       耗材上报：支持                     │
│                                                                  │
│ 物理偏移校正                                        [打印校正页] │
│              上  [  0 ] dot                                      │
│   左 [  0 ] dot        右 [  0 ] dot                             │
│              下  [  0 ] dot                                      │
│   每次更换纸卷后都可能需要重新校正，即使是同型号纸。             │
│                                                                  │
│ Profile                                              [新建]      │
│  ● 原厂 50×30    密度 3  纸型 间隙纸  标签 50×30mm  边距 1mm     │
│  ○ 第三方 40×20  密度 4  纸型 间隙纸  标签 40×20mm  边距 0mm     │
│                                                     [探测][暂停] │
└──────────────────────────────────────────────────────────────────┘
```

### 6.1 偏移归属打印机，不归 Profile

**偏移是设备的物理属性**：每次给设备换纸——**就算是同型号纸**——都可能产生位移，
需要重新校正。它描述的是「这台机器现在的走纸位置」，不是「这种纸该怎么排版」。

因此：

- `偏移 (offsetX / offsetY)` → **Printer**，单位 dot。
- `边距 (上/右/下/左)` → **Profile**，单位 mm，默认 0，UI 支持四值联动。

> **数据迁移**：当前 `Profile` 上有 `offsetXMm` / `offsetYMm`，需要迁走。
> 已有 Profile 的偏移值应迁移到其所属 Printer（若一台打印机的多个 Profile
> 偏移值不同，取默认 Profile 的值，并在迁移日志中记录被丢弃的值）。

### 6.2 标签数据并入 Profile

Profile 代表「这台打印机 + 当前这卷纸」，因此纸张尺寸属于它：

| 字段 | 单位 | 说明 |
|---|---|---|
| `labelWidthMm` / `labelHeightMm` | mm | 纸张尺寸 |
| `marginTopMm` / `RightMm` / `BottomMm` / `LeftMm` | mm | 四边边距，默认 0 |
| `density` / `labelType` / `speed` | — | 现有字段 |

**标签间距暂不处理**，全部走默认值。

**选择 Profile 时，画布尺寸自动改为 Profile 的纸张尺寸。** 已有的元素位置**不做任何自动调整**，
由用户自己重新排版。

理由：选了 40×20 的纸却在 50×30 的画布上排版，最后一定打错。让画布始终等于真实纸张，
是唯一不会骗人的做法。

自动缩放或自动重排元素**不做**——那等于替用户做排版决定，而且缩放后的坐标不再落在
dot 网格上，会把 §4.3 建立的对齐保证破坏掉。改变画布后：

- 越界的元素按 §4.8 的规则标记为警告，用户能立刻看到哪些需要动。
- 画布尺寸变更计入撤销历史，用户可以撤回这次 Profile 切换。
- 若当前设计有未保存修改且新尺寸更小，切换前提示一次。

### 6.3 校正流程

「打印校正页」打印一张带刻度的十字标记，用户量出偏差后填入四个方向的 dot 值。

**本期做。** 不做的话用户只能靠试打普通标签来估偏移，而偏移每次换纸都要重调，
这个动作的频率足够高，值得一个专门的工具。

校正页内容：四边各一组带刻度的标尺线，中心一个十字。用户量出十字偏离纸张中心的
距离，直接读出需要填入的 dot 值。校正页与普通打印一样**消耗纸张**，
因此沿用与打印相同的确认规则（FR-017）。

## 7. 打印队列 / 打印历史

维持现有设计，从编辑器右侧面板提升为独立页面。

- **队列**：进行中（带进度）、排队中；可取消；可暂停/恢复整台打印机的队列。
- **历史**：已完成 / 失败 / 已取消；失败项可重新提交。
  历史条目显示的是**打印时的内容快照**（FR-050），
  模板后来被改动不会影响历史记录的显示。

**保持分开**，两个独立的侧边栏条目。两者的操作完全不同：
队列是「管理正在发生的事」（取消、暂停），历史是「查证已经发生的事」（追溯、重提）。

**只放客户端偏好**，存 localStorage，每个浏览器一份。

|---|---|

| 新建标签默认尺寸与 dpi | |

### 8.1 服务端配置不进界面

空跑模式、日志级别、历史保留期等**继续走环境变量**。

本系统不做认证，**任何能访问到的人都能改全局设置**。修改环境变量需要能登到机器上，
这本身是一道天然的权限边界；界面上没有任何边界可言。
空跑开关尤其不该放进界面——它的全部价值就在于不会被顺手关掉。

### 8.2 打印机相关设置不进本页

**打印机页管每台设备，设置页管全局。** 偏移、Profile、密度都留在打印机页。

### 8.3 语言切换与服务端文案（L1）

服务端返回的错误是**已经措好辞的**（`{ code, what, why, next }` 四段），
前端原样显示。这是有意的：同一个故障不会有两套说法，CLI 也共用同一套文案。

界面切成英文后，如果服务端错误还是中文，**半个界面切了、报错没切**——
这比不做语言切换更糟。

因此采用 **L1**：

- 前端请求携带 `Accept-Language`，**服务端按语言返回文案**。
- 两层 i18n，职责不重叠：

```
packages/server/src/i18n/{zh-CN,en-US}.ts   设备错误码 + 应用错误（CLI 共用）
packages/web/src/i18n/{zh-CN,en-US}.ts      界面文字（服务端不知道的部分）
```

语言偏好存 localStorage。没有认证，所以「跟着用户走」只能靠浏览器本地存储——
换个浏览器会回到默认，这个代价可以接受。

### 9.4 必须一并修复的三处缺陷

本期的编辑器工作会直接踩到这三处，必须一起修：

**① 二维码渲染成一维条码（硬伤）**

`packages/shared/src/ir-to-svg/index.ts` 的 `case 'qrcode'` 里硬编码了
`symbology: 'code128'`，而 `SYMBOLOGY_TO_BCID` 表根本没有 `qrcode` 项。

实测：声明 15×15 mm（120×120 dot）的二维码，实际画出一条宽 **486 dot** 的
Code 128 条码，比 400 dot 的画布还宽。

前后端共用同一份 `ir-to-svg`，所以编辑器预览和实际打印**一致地错**——
这正是它没被测试抓住的原因。修复需要接上 bwip-js 的 `qrcode` bcid，
并把 `errorCorrectionLevel` 映射到 `eclevel`。

**② 条码的 `widthMm` 在渲染时被完全忽略**

`ir-to-svg/index.ts` 的条码分支注释写着「No scaling」，实际宽度
= 模块宽度 × 模块数，而模块宽度来自 `IrToSvgOptions.barcodeModuleWidthDots`
这个**全局渲染选项**。

后果：编辑器里拖动条码的宽度手柄，对打印结果没有任何影响；
同一张标签上的两个条码也无法使用不同的模块宽度。
修复方式即 §9.1 —— 把 `moduleWidthDots` 变成元素属性。

**③ 偶数模块宽度限制不成立**

`packages/shared/src/barcode/index.ts` 的 `assertEvenModuleWidth` 强制偶数，
实测证明不必要（§4.6），白白砍掉一半可用宽度。
放宽为整数 ≥ 2，同时修改断言「拒绝奇数模块宽度」的那条测试——
它在断言一条不存在的规则。

### 9.5 可变内容条码的宽度

**可变字段带来一个后果**：条码内容为 `{$var: fieldName}` 时，
模块数在设计时是未知的（Code 128 的模块数随内容长度变化）。

因此：

- 条码的**模块宽度**是设计时确定的（存进 IR）。
- 条码的**实际宽度**在渲染时才知道，逐张标签可能不同。
- 元素的 `widthMm` 对可变条码而言是**预估的包围盒**，用于越界检查与预览；
  编辑器应以字段的示例值估算，并提示「实际宽度随内容变化」。
- 越界检查必须在**打印前对每张标签的实际内容**再跑一次，
  而不只是在设计时对示例值跑一次。

## 附二：003 新增的界面（变量与表格数据源）

本稿写于「可变字段」的年代，那套机制已在 003 中整体移除。下面是取代它的界面。

### 属性栏的第二个页签：变量

原「可变字段」页签改为「变量」。差别不只是名字：

- **没有「绑定」这个概念了。** 引用写在文字/条码/二维码的内容里（`零件 ${sku} 号`），
  一个元素可以引用多个变量，也可以在引用之间夹字面文本——这是旧的整元素绑定表达不了的。
- 页签里只登记两种变量：**设计期常量**与**自增**。数据源的列不需要登记，因为设计已经
  绑定了一张表，列名本身就是引用。
- **改名不改写元素内容。** 引用是手写在内容里的，编辑器没有理由去改别人的文字；
  改名之后未解析警告会说清楚哪里断了。

同一页签顶部是**数据源绑定**：一个下拉框（可清空），选中之后列出列名，点一下把
`${列名}` 追加到当前选中的元素——列名靠记忆手打出来的引用会静默解析不出东西。

绑定失效（所绑的表被删、或引用的列没了）时，这里和模板库列表各显示一条警告。该状态
读取时计算、不落库:存的状态会漂移,而漂移的方向恰好是「显示正常、实则已断」。

### 数据源列表 `/data-sources`

每个数据源显示行数与列名——列名是被引用的东西，是挑表时真正要看的。操作：编辑、
改名、替换、删除。

删除的确认说的是**表里的行会被删掉、无法恢复**，不是「有几个设计在用它」。引用它的
设计不会被阻挡：列引用是裸名，重新绑到另一张同形状的表就全部复原。

### 数据源编辑 `/data-sources/:id`

shadcn Table + TanStack。可改单元格、加行、删行，每页 10 行。

**不能改列名。** 列名是设计引用的名字,从这里改会静默弄坏引用它的设计。要改列集就
重新上传,那条路径上能把「哪些列会消失、哪些设计会断」摆出来。

选中一格后 Ctrl+V 可粘贴从 Google 表格/Excel 复制的区块。超出末行会追加;**超出最后
一列会被拒绝**——凭空多出的列没有名字。

### 打印对话框的行选择区

设计绑定了数据源时出现。每页 10 行，三种选法：勾选、输入区间（`5-12`）、全选。

**全选按钮上写着行数**（「全选（200 行）」）。不写行数的全选是那种「悄悄只选当前页」
的控件,别人要两百张时它印十张,而屏幕上没有任何东西能说清是哪种。

底部固定一条提示:**未按行检查内容宽度**。这是 FR-045 的诚实后果——逐行编码来量宽度
正是被否决的做法,而沉默会被读成「检查过,没问题」。

预览显示打印顺序上的第一张。

### 序号池（设置页内）

不新开页面：序号池建得少、用的时候是从设计的变量面板里选，独立页面会是一个没人开
第二次的标签页。

当前值只读——它由已打印的任务推导，旁边再放一个可编辑的字段，等于在证据边上摆第二份
数字。重置的确认说明**会与已贴出的标签重号**,而不是一句「确定吗」。
