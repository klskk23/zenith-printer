# Research: 标签工作流与说明文字清理

**Feature**: `006-label-print-flow` | **Date**: 2026-09-22

所有事实都在本仓库里核实过，注明了出处。没有需要外部查证的未知项。

## 1. 打印任务带的是画布内容，不是标签 id

- **事实**：`packages/web/src/features/print/print-dialog.tsx` 的 `jobBody()` 提交 `ir`（画布上的标签内容），`templateId` 只在有保存过的标签时附带，用于历史归属与序号领用。
- **结论**：「设计」页按「继续」不需要先保存——打印未保存的修改是既有能力，不是本功能新增的。FR-024 只是把它钉住。
- **代价**：服务器上的版本与打出来的实物可能不一致。这是 2026-09-22 的明确选择（离开即放弃，保存只由「保存」负责）。

## 2. 裁切有两种来源，别混成一句话

- **事实**：`POST /print-jobs/preflight` 的处理函数是 `checkLabel(content.ir, values, 0)`——行索引写死 0，它检查的是**这张设计本身**，不是批次里的每一行。
- **事实**：`/api/preview` 的每次渲染在响应头里带 `X-Clipped`，那是**这一行**的答案。
- **决定**：「确认」页那行红字只说超出多少毫米（来自预检），不声称有几张受影响；展开逐张看时，被裁的那张按自己的 `X-Clipped` 标红。
- **否决**：在前端算裁切。做不到逐行，且会和服务端的判断分叉。

## 3. 幂等键与不安全上下文

- **事实**：`lib/random-id.ts` 存在，因为 `crypto.randomUUID()` 只在安全上下文可用，而本服务是局域网明文 HTTP。对话框用 `useMemo(() => randomId(), [])`——每次打开铸一个。
- **决定**：改为每次进入「确认」页铸一个。重试沿用（FR-059）；回「打印」页改了选择再进来换新键。
- **保留的测试**：`insecure-context.dom.test.tsx` 改为指向「确认」页。

## 4. 行选择已经解决过一次，别重做

- **事实**：`features/print/row-selection.tsx` + `selection.ts` 提供三种方式：逐行勾选、按区间输入（`parseRange`）、整表全选（`kind: 'all'`，按钮上写明覆盖多少行），服务端分页每页 `ROW_PAGE_SIZE` 行，带 key 列的表按 key 记选择以便刷新后不错位。
- **决定**：「打印」页原样复用这个面板，只把它放在页面最后一节。`keyByOrdinal` 的累积从对话框上移到会话。
- **否决**：改成一次拉全表 + 前端虚拟滚动。1284 行要多拉 128 倍数据，且要重做 key 对齐这套逻辑。

## 5. 预估耗时的来源

- **事实**：现有对话框底部没有耗时；耗时是本功能新增的显示项。`GET /printers` 的 capabilities 里没有速度字段。
- **决定**：用一个保守的常量估算（每张固定毫秒 × 张数），放在 `flow.ts` 里，文案写「约 N 秒」。它是数量级提示，不是承诺；`data-model.md` 记下这个常量的来历。
- **否决**：从打印历史回归实测速度。数据稀疏（新部署没有历史），且会让「约 4 秒」在不同机器上抖动，反而更不可信。

## 6. 步条的可达性规则

- **事实**：`app/routes.ts` 目前只有扁平的 page kind，没有层级概念。
- **决定**：可达性是纯函数：`stepsFor({ page, hasPrinter, hasRows })`。① 永远可达；② 有标签就可达；③ 有标签就可达；④ 需要「可提交」（选了打印机、绑了数据源则有勾选的行）。未到的步不可点（FR-003）。
- **否决**：把可达性藏进组件。纯函数能直接测，也让「直接打开 confirm 地址退回 print」（FR-065）用同一个判断。

## 7. Tooltip 组件：shadcn 的，而不是自己写

- **事实**：`components/ui/` 有 29 个 shadcn 组件，没有 tooltip；`@radix-ui/react-tooltip` 未安装。架构规则要求优先 shadcn/ui，自建必须说明缺少的替代。
- **决定**：安装 `@radix-ui/react-tooltip`，按现有组件的写法（cva 变体 + `cn()` + Nocturne 令牌）加 `components/ui/tooltip.tsx`。
- **事实（限制）**：Radix Tooltip 的内容不可选中，鼠标移开即消失——所以要带走的值（服务账号地址）不能放里面。这直接导出了 `<ValueHint>` 用 Popover 的设计。
- **否决**：用 `title` 属性。它的样式不可控、延迟不可控，且在深色界面里是系统白底。

## 8. 复制到剪贴板

- **事实**：`navigator.clipboard` 在不安全上下文（明文 HTTP）里不可用——与 `randomId()` 同一个原因。
- **决定**：`<ValueHint>` 的「复制」先试 `navigator.clipboard.writeText`，失败则退化：把地址选中（`selectAllText`）并把按钮文字换成「按 Ctrl+C 复制」。地址本身始终可见可选，所以最坏情况也能拿走。

## 9. 哪些文案是"必留"

- **事实**：`.agents/rules/ux-and-api.md` 要求错误说明「发生了什么、可能原因、下一步」；宪章原则 III 要求术语与错误呈现一致。
- **决定**：三档的"必留"档由这条规则定义，不是凭感觉：错误、不可撤销操作的确认、异常状态说明、空状态引导。清单见 `contracts/hint-tiers.md`。
