# 环境搭建与手工验收：Google Sheets 数据源

---

## 一、准备机器身份（一次性，由部署方做）

1. 在 Google Cloud Console 建一个项目（或用现成的）
2. **启用 Google Sheets API**（研究阶段确认过：这一步不做，后面全部 403）
3. 建一个服务账号，为它创建 JSON 密钥并下载
4. 记下密钥里的 `client_email`，形如
   `zenith@my-project.iam.gserviceaccount.com` —— 这就是要分享给的对象

密钥文件放到服务能读、别人读不到的地方：

```bash
sudo install -o zenith -g zenith -m 0400 ~/Downloads/key.json /etc/zenith/google.json
```

`0400` 且属主为服务用户：**这份文件能读到所有被分享给它的表格**。

在 systemd 单元里指出路径：

```ini
Environment=ZENITH_GOOGLE_CREDENTIALS=/etc/zenith/google.json
```

未设置该变量时，界面上链接 Google 表的入口不出现，其余功能不受影响。

## 二、分享一张表

在 Google 表格里「共享」→ 填入上面那个 `client_email` → 权限选**查看者**即可（本功能
只读，也只申请了只读权限）。

> 每一张要用的表都要分享一次。这是服务账号相对 OAuth 的代价，也是它的好处：系统能看见
> 的，恰好就是你分享过的那几张。

## 三、手工验收

### A. 接入（FR-006~012）

1. 数据源页 → 「链接 Google 表格」
2. 粘贴表格链接 → 应列出该表格的全部工作表
3. 选一个 → 应出现列名、至少 3 行数据、以及一个已填好工作表名的名称框
4. 确认 → 数据源出现在列表里，可被设计引用

**要看的**：预览里的取值与表格里显示的**逐字相同**。特别留意一列文本 `007` 和一列
日期——这是 FR-010 与 SC-002 的正面。

### B. 命名冲突（FR-008a、FR-008b）

1. 把名称框改成一个已存在的数据源名 → 应当场指出重名并拒绝创建，而不是创建后才报错
2. 把同一张表再链接一次、取个不同的名字 → 应当成功，两者各自独立

### C. 刷新（FR-013~018c）

1. 在 Google 那边追加几行 → 回来按刷新 → 行数变化，刷新时间更新
2. 打开打印对话框 → 那里也有刷新入口
3. 勾选若干行 → 按刷新 → **选择应被清空**，并说明原因
4. 刷新进行中 → 按钮应显示进行中且不可再按

### D. 只读与解绑（FR-019~025）

1. 打开链接的数据源 → 单元格不可编辑、不能加行、没有「替换」
2. 解绑 → 确认框应说明「此后不再能刷新、行由本地维护」，而不是只问「确定吗」
3. 确认后 → **行还在**，且三条编辑路径都恢复可用

### E. 失败（FR-026~030）

| 怎么造 | 应看到 |
|---|---|
| 在 Google 那边取消分享，再刷新 | 说明需要分享给哪个邮箱；**旧行还在**；仍能打印 |
| 删掉那张表，再刷新 | 说明表格不存在；旧行还在 |
| 删掉那个工作表，再刷新 | 说明工作表不存在（区别于上一条） |
| 断开服务器外网，再刷新 | 说明连不上；旧行还在 |
| 把表撑到 10,001 行，再刷新 | 拒绝本次刷新、旧行保留、说明超出多少；**不截断** |

最后一条尤其要盯：截断的后果是打了 1~10000 行的标签，而 10001 行之后的存在与否无人
知晓。

### F. 表头变化（FR-031~034）

1. 在 Google 那边**加**一列 → 刷新 → 直接应用，不打扰
2. 用该数据源的某列做一个设计（内容里写 `${收件人}`）
3. 在 Google 那边把「收件人」改名 → 刷新 → 应暂不应用，并**列出那个设计**
4. 取消 → 列与行都不变
5. 再刷新并确认 → 应用；那个设计的卡片上出现绑定告警

### G. 命令行（FR-035~037）

```bash
zenith data-source-refresh --id <id> --server http://localhost:3000
echo $?                        # 成功 0

zenith data-source-refresh --id <id> --json | jq .outcome
```

改名一列后不加 `--confirm-column-change` 执行 → 退出码 4，输出说明需要确认；加上之后
→ 0。

## 五、需要联网的两点（手工核实，**不是测试**）

这两条**必须实测**，不能靠推断——研究阶段已确认官方文档未覆盖它们。

它们不做成自动化测试：宪章「测试 MUST 确定性：禁止依赖真实时钟、随机数或**网络**」是
无条件的，而其隔离条款只为「需要**真实硬件**的测试」开口，措辞未涵盖「需要外部网络
服务」。与其塞进一个不覆盖的口子，不如放在这里——它们核实的本就是**关于 Google 的事实**，
而不是本系统的行为；本系统的行为已由假实现全覆盖。

### HW-1：取值是否逐字保真

在一张已分享的表里准备三列：

| 列 | 单元格内容 | 期望读到 |
|---|---|---|
| 文本 | 文本格式的 `007` | `007`，不是 `7` |
| 日期 | 表格里显示为 `2026-08-22` | 与显示一致 |
| 货币 | 显示为 `¥19.90` | 与显示一致，含符号 |

链接这张表 → 看预览 → 逐字比对。**任何一格对不上，就是 FR-010 与 SC-002 被破坏了。**
把结论回写到 `research.md` R3。

### HW-2：未分享的表格返回 403 还是 404

1. 找一张**存在但未分享**给机器身份的表格，复制其链接
2. 在链接对话框里粘贴 → 观察报错

这决定「需要把表分享给 X」这句提示能否说出口——这是本功能最常见的首次失败，说错了人会
跑去查表格是不是被删了。

在核实之前，实现须让 404 也附带「或者尚未分享给 `<邮箱>`」。核实之后按结果收敛该文案，
并回写到 `research.md` R7。
