# Feature Specification: Google Sheets 数据源

**Feature Branch**: `004-google-sheets-source`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "按照 docs/google-sheets-data-source.md 实现 google sheet 数据源功能"

## Clarifications

### Session 2026-08-22

- Q: 链接的数据源如何命名，才不与既有的名称唯一性约束冲突？ → A: 预览确认环节提供可编辑的名称框，默认填入工作表名；重名时当场指出并要求改
- Q: 一个链接的数据源能否变回普通数据源？ → A: 可以解绑：保留当前的行，断开来源，恢复为可编辑；因不可逆需确认
- Q: 谁可以链接和刷新 Google 表？ → A: 接受现状并显式记录——凡能访问本服务者皆可；本功能不引入独立的准入控制
- Q: 刷新是同步等待还是后台任务，卡住了怎么办？ → A: 同步请求，期间显示进行中并禁止重复触发，设超时上限，超时按刷新失败处理
- Q: 刷新是否要留下可追溯的记录？ → A: 每次刷新记一条结构化结论（数据源、结果、前后行数、失败原因），不含行内容

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把一张 Google 表接成数据源 (Priority: P1)

运营在 Google 表格里维护当天的出货清单。她把那张表分享给系统的机器人邮箱，回到标签
系统，粘贴表格链接，从列出的工作表里选中「本月出货」，屏幕上出现识别到的列名、前几
行，以及一个已经填好「本月出货」的名称框。确认无误后，这张表成为一个数据源，和上传 CSV 得到的数据源一样可以被设计引用、
被打印任务选行。

**Why this priority**: 这是整个功能的地基，也是唯一一条不依赖其余任何故事就能独立
交付价值的路径。没有它，刷新和失败处理都无从谈起。

**Independent Test**: 分享一张表、粘贴链接、确认列名、创建数据源，然后用它打印一张
标签。全程不需要刷新、不需要处理任何失败，即可验证价值已经交付。

**Acceptance Scenarios**:

1. **Given** 一张已分享给机器人邮箱的表格，**When** 运营粘贴它的链接，**Then** 系统
   列出该表格的所有工作表供选择
2. **Given** 已选定工作表，**When** 系统读取该工作表，**Then** 在创建之前展示识别到的
   列名与数据行，供人确认
3. **Given** 预览中的列名与实际相符，**When** 运营确认，**Then** 创建出一个数据源，其
   列与行来自该工作表，名称为她在该环节确认的名称
4. **Given** 预览环节填入的名称与既有数据源重复，**When** 运营尝试确认，**Then** 系统当场
   指出重名并要求改，不创建数据源
5. **Given** 一张未分享给机器人邮箱的表格，**When** 运营粘贴它的链接，**Then** 系统说明
   它读不到这张表、需要分享给哪个邮箱，而不是给出一个通用错误
6. **Given** 单元格里是文本 `007`，**When** 数据被读入，**Then** 数据源里仍是 `007`

---

### User Story 2 - 表改了之后把数据取回来 (Priority: P1)

出货清单在 Google 那边被追加了二十行。运营回到系统，按下刷新，数据源的行被整表替换，
界面显示这次刷新的时间。她也可以在打印对话框里就地按下同一个刷新，不必先退出去。

**Why this priority**: 与 P1 同级，因为「不必重新上传 CSV」正是选择 Google 表格而非
本地文件的全部动机。只有故事 1 而没有它，这个功能与既有的 CSV 导入没有区别。

**Independent Test**: 改动 Google 表的内容，在系统里按刷新，确认行随之改变、且刷新
时间被更新。

**Acceptance Scenarios**:

1. **Given** 一个链接的数据源，**When** 运营按下刷新且读取成功，**Then** 行被整表替换，
   并记录本次刷新的时间
2. **Given** 一个链接的数据源，**When** 任何界面展示它，**Then** 上次刷新的时间可见
3. **Given** 打印对话框已打开且尚未勾选行，**When** 运营在对话框内按下刷新，**Then** 行
   被更新，且行选择界面基于新的行重新呈现
4. **Given** 运营已经勾选了若干行，**When** 他按下刷新，**Then** 当前的行选择被清空，
   并说明原因
5. **Given** 一个链接的数据源，**When** 系统处于任何状态，**Then** 不会在无人操作时自动
   刷新

---

### User Story 3 - 链接的表在本地不可编辑 (Priority: P2)

运营打开一个链接的数据源，看到的是只读的表格：单元格不能改、不能加行、不能删行、
不能上传文件替换它。界面说明这张表的内容来自 Google，要改就去那边改。若她确实想接管
这张表，可以解除链接：行留下，来源断开，数据源变回普通的可编辑表。

**Why this priority**: 防止一类无声的数据丢失——本地改一笔、下次刷新被抹掉，而没有
任何人被告知。它依赖故事 1 才有意义，但独立于故事 2。

**Independent Test**: 创建一个链接的数据源，尝试编辑单元格、加行、替换，确认三条路径
都不可用且给出了原因；再解除链接，确认行还在且三条路径都恢复可用。

**Acceptance Scenarios**:

1. **Given** 一个链接的数据源，**When** 运营打开它的编辑页，**Then** 表格为只读，且
   界面说明内容来自 Google
2. **Given** 一个链接的数据源，**When** 运营查看它的操作，**Then** 「替换」不可用
3. **Given** 一个由本地文件创建的数据源，**When** 运营打开它，**Then** 编辑能力与既有
   行为完全一致，不受本功能影响
4. **Given** 一个链接的数据源，**When** 运营解除链接并确认，**Then** 当前的行原样保留，
   数据源恢复为可编辑，且不再提供刷新
5. **Given** 运营点击解除链接，**When** 确认框出现，**Then** 它说明此后不再能刷新、行将
   由本地维护，而不是只问一句「确定吗」

---

### User Story 4 - 刷新失败时仍然能打印 (Priority: P2)

刷新时网络不通，或那张表已被删除，或分享被撤销。系统说明发生了什么，保留上一次取到
的行，运营仍然可以用这些数据打印——只是知道它们不是最新的。

**Why this priority**: 保证外部依赖的故障不会让打印停摆。价值在故障时才体现，因此排在
正常路径之后。

**Independent Test**: 撤销分享后按刷新，确认给出了原因、旧行仍在、且仍能打印。

**Acceptance Scenarios**:

1. **Given** 一个链接的数据源，**When** 刷新因任何原因失败，**Then** 上一次取到的行原样
   保留
2. **Given** 刷新失败，**When** 运营继续操作，**Then** 用现有行打印不被阻止
3. **Given** 刷新失败，**When** 系统给出说明，**Then** 说明区分「读不到这张表」「工作表
   不存在」「行数超限」等不同原因，而不是一句通用失败
4. **Given** 表格的行数超过上限，**When** 运营刷新，**Then** 这次刷新被拒绝、旧行保留，
   并说明超出多少；行不会被截断

---

### User Story 5 - 表头变了要先说清楚 (Priority: P3)

Google 那边把「收件人」改成了「客户名称」。运营按下刷新，系统没有直接照搬，而是指出
哪些列消失了、哪些设计引用了它们，等他确认后才应用。若只是新增了一列，则直接应用，
不打扰他。

**Why this priority**: 列名就是引用名，改名会让设计取不到值。它是最容易被忽略、后果
又只在印出来时才显现的一类变化。排在 P3 是因为其余故事不依赖它。

**Independent Test**: 在 Google 表里改掉一个被设计引用的列名，按刷新，确认系统列出了
受影响的设计并要求确认。

**Acceptance Scenarios**:

1. **Given** 一个链接的数据源，**When** 刷新发现表头只是新增了列，**Then** 直接应用，
   不要求确认
2. **Given** 有设计引用列 X，**When** 刷新发现 X 已消失或被改名，**Then** 暂不应用，列出
   受影响的设计并要求确认
3. **Given** 运营确认了列的变化，**When** 变化被应用，**Then** 受影响的设计在其卡片与
   设计页上显示既有的绑定告警
4. **Given** 运营取消了确认，**When** 操作结束，**Then** 数据源的列与行都不变

---

### Edge Cases

- 粘贴的不是 Google 表格链接，或链接里没有可识别的表格标识 → 说明期望的链接形式
- 表格存在但一个工作表都没有，或选中的工作表是空的 → 说明并拒绝创建，不产出零列数据源
- 选中的工作表首行有空单元格或重复列名 → 与既有 CSV 导入的规则一致地处理并说明
- 机器人凭据未配置 → 链接入口不可用，并说明需要由部署方配置
- 机器人凭据已配置但无效或已过期 → 说明是凭据问题，而非表格问题
- 选中的工作表在创建之后被改名或删除 → 归入刷新失败，保留旧行
- 同一张表被链接为两个数据源 → 允许（第二次须在预览环节另取名称），两者各自独立刷新
- 数据源被删除 → 与既有行为一致；引用它的设计显示绑定告警
- 解绑之后再次链接同一张表 → 视作一次全新的链接，须重新走预览确认并另取名称
- 刷新正在进行时再次按下刷新 → 界面上不可触发；即便请求仍到达服务端，也不产生两次并发写入
- 表格里的合并单元格、公式、错误值（如 `#REF!`）→ 按其显示出来的文本取值

## Requirements *(mandatory)*

### Functional Requirements

**凭据与配置**

- **FR-001**: 系统 MUST 以一个由部署方配置的机器身份读取 Google 表格，该身份 MUST NOT
  依赖任何个人用户的登录或授权
- **FR-002**: 机器身份的凭据 MUST 由部署方通过运行环境提供，界面 MUST NOT 提供上传或
  修改凭据的入口
- **FR-003**: 界面 MUST 只读地显示凭据是否已配置，以及需要把表格分享给哪个邮箱
- **FR-004**: 凭据内容 MUST NOT 出现在任何级别的日志中
- **FR-004a**: 系统 MUST NOT 通过任何接口返回凭据内容或其任何片段。对外可见的只有
  「是否已配置」与机器身份的邮箱地址
- **FR-005**: 凭据未配置时，链接 Google 表格的入口 MUST 不可用，并说明需要由部署方配置

**链接一张表**

- **FR-006**: 用户 MUST 能通过粘贴表格链接来指定要接入的表格
- **FR-007**: 系统 MUST 列出该表格中的工作表供用户选择
- **FR-008**: 系统 MUST 在创建数据源之前展示识别到的全部列名与至少 3 行数据（数据不足
  3 行时展示全部），并要求用户确认
- **FR-008a**: 该确认环节 MUST 提供可编辑的名称输入，默认填入所选工作表的名称
- **FR-008b**: 名称与既有数据源重复时，系统 MUST 在此环节当场指出并要求改，MUST NOT
  自动加后缀，也 MUST NOT 在用户确认之后才报错
- **FR-009**: 系统 MUST 以所选工作表的**首行为表头**，表头即列名
- **FR-010**: 取值 MUST 采用单元格显示出来的文本；系统 MUST NOT 对取值做类型推断
  （`007` 必须仍是 `007`，日期必须保持其显示形式）
- **FR-011**: 链接产生的数据源 MUST 与既有数据源在引用、行选择、打印上的行为完全一致
- **FR-012**: 系统 MUST 记住该数据源的来源（表格与工作表），以便日后刷新

**刷新**

- **FR-013**: 用户 MUST 能手动刷新一个链接的数据源，刷新 MUST 整表替换其行
- **FR-014**: 系统 MUST NOT 在无人操作时自动刷新
- **FR-015**: 打印对话框 MUST 提供刷新入口，且刷新结果 MUST 在行选择界面呈现之前生效
- **FR-016**: 刷新 MUST 清空当前的行选择，并说明原因
- **FR-017**: 系统 MUST 在展示链接数据源的地方显示上次刷新的时间
- **FR-018**: 并发的刷新请求 MUST NOT 导致同一数据源被写入两次
- **FR-018a**: 刷新 MUST 同步完成——用户发起后等待其结束，不产生需要另行查询的后台任务
- **FR-018b**: 刷新进行中，界面 MUST 显示进行中状态，且 MUST 禁止对同一数据源重复触发
- **FR-018c**: 刷新 MUST 有超时上限；超时 MUST 按刷新失败处理（保留旧行、给出说明），
  MUST NOT 无限等待

**只读**

- **FR-019**: 链接的数据源 MUST 在本地只读：不可编辑单元格、不可增删行
- **FR-020**: 链接的数据源 MUST NOT 允许用本地文件替换其内容
- **FR-021**: 界面 MUST 说明该数据源为只读及其原因
- **FR-022**: 本功能 MUST NOT 改变非链接数据源的任何既有行为
- **FR-023**: 用户 MUST 能解除一个数据源的链接。解绑 MUST 保留当前的行，MUST 移除其来源
  信息，且该数据源 MUST 随之恢复为可编辑的普通数据源
- **FR-024**: 解绑不可逆（来源信息不再保留），因此 MUST 在执行前要求确认，确认文案 MUST
  说明后果：此后不再能刷新，且行将由本地维护
- **FR-025**: 解绑之后的数据源 MUST 在引用、编辑、替换、删除上与由本地文件创建的数据源
  完全一致

**失败与限制**

- **FR-026**: 刷新失败时系统 MUST 保留上一次取到的行
- **FR-027**: 刷新失败 MUST NOT 阻止用现有行打印
- **FR-028**: 失败说明 MUST 区分原因：读不到该表格、工作表不存在、凭据无效、行数超限、
  网络不可达、超时
- **FR-029**: 单个数据源的行数上限 MUST 与既有上限一致；超出时 MUST 拒绝本次刷新并保留
  旧行，MUST NOT 截断
- **FR-030**: 所有面向用户的失败说明 MUST 包含三要素：发生了什么、可能的原因、下一步
  可执行的操作

**表头变化**

- **FR-031**: 刷新发现表头只是新增列时，系统 MUST 直接应用，MUST NOT 要求确认
- **FR-032**: 刷新发现有列消失或被改名时，系统 MUST 暂不应用，MUST 列出引用了这些列的
  设计，并要求确认
- **FR-033**: 用户取消确认时，数据源的列与行 MUST 保持不变
- **FR-034**: 列变化应用之后，受影响的设计 MUST 通过既有的绑定告警机制显示问题

**命令行**

- **FR-035**: 系统 MUST 提供一条刷新指定数据源的命令行指令
- **FR-036**: 该指令的行为 MUST 与界面上的刷新完全一致，包括成功、失败与表头变化时的
  处理；MUST NOT 存在只有命令行才有或只有界面才有的差异
- **FR-037**: 该指令 MUST 支持机器可读输出，并以稳定的退出码区分成功、目标不存在、
  服务不可达、刷新失败

**可观测性**

- **FR-038**: 每次刷新 MUST 在结构化日志中留下一条结论，包含：数据源标识、结果（成功 /
  失败 / 待确认）、替换前后的行数、以及失败时的原因分类
- **FR-039**: 该记录 MUST NOT 包含任何行内容。业务数据不进日志，与 FR-004 守的是同一条
  边界，只是换了个入口

**可测试性**

- **FR-040**: 默认测试套件 MUST 能在没有网络与真实 Google 凭据的情况下完整运行

### Key Entities *(include if feature involves data)*

- **数据源来源**：一个链接的数据源额外携带的信息——它来自哪个表格、哪个工作表、上次
  成功刷新是什么时候。非链接的数据源没有这些信息；解绑会移除它，且不可恢复。
- **刷新结果**：一次刷新的结论——成功并替换了多少行，或失败及其原因，或因表头变化而
  待确认及受影响的设计清单。
- **机器身份**：系统用来读取表格的身份，其对外可见的部分只有一个邮箱地址，用于告知
  用户该把表格分享给谁。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 运营在把表格分享给机器人邮箱之后，能在 2 分钟内完成从粘贴链接到数据源
  可用的全过程，无需任何人协助
- **SC-002**: 100% 的取值与单元格显示内容一致——前导零、长数字、日期均不发生改变
- **SC-003**: 表格内容更新后，运营在系统内 3 次点击以内让数据源反映最新内容
- **SC-004**: Google 侧不可用时，100% 的打印任务仍可用上一次取到的数据完成
- **SC-005**: 表格行数超出上限时，0 行被静默丢弃
- **SC-006**: 被设计引用的列消失时，100% 的此类刷新在应用前得到确认，且确认界面列出了
  全部受影响的设计
- **SC-007**: 在完全没有外部网络连接的环境下，本功能的全部行为仍可被完整验证
- **SC-008**: 刷新在任何情况下都会在有限时间内给出结论——成功、失败或超时，界面不会
  停留在进行中状态
- **SC-009**: 事后调查「某批标签的数据从哪一次刷新而来」时，100% 的刷新都能在日志中找到
  其结论；0 条日志包含行内容

## Assumptions

- 运营有权把业务表格分享给一个机器身份的邮箱地址；数据合规问题由业务侧确认
- **本系统目前没有任何鉴权**（见 `docs/design-consensus.md`：「局域网 + VPN，不暴露公网；
  认证后续再做」）。因此凡能访问本服务的人都可以链接表格、刷新、以及读取行数据。本功能
  接受这一前提，不引入只作用于自身的准入控制——那会造出一个与全站其余部分不一致的孤岛。
  它同时构成「登录」功能应尽早排上的一条依据：本功能把 Google 上的业务数据搬进了这条
  边界之内
- 部署方有能力配置运行环境（与配置监听地址、图片存储目录属同一类工作）
- 表格的首行是列名。首行不是列名的表格，由创建前的预览确认环节暴露，用户回 Google
  那边调整后重试
- 手动刷新的频率远低于外部服务的调用限额；限额相关的失败归入 FR-028 的「读不到」一类
- 数据源名称在系统内唯一（既有约束）。链接时的名称由用户在预览确认环节决定，默认填入
  工作表名；创建之后的改名行为与既有数据源一致
- 一个设计仍然只能引用一个数据源；本功能不改变这条约束
- 打印任务在提交时快照行值这一既有行为不变——刷新只影响此后新建的任务

## Out of Scope

- 使用个人 Google 账号的 OAuth2 授权
- 用 Google 账号登录本系统，以及本系统自身的鉴权
- 定时自动刷新（部署方可用命令行指令配合定时任务自行实现）
- 向 Google 表格写回数据
- 用 A1 区间指定读取范围
- 通过公开链接或 API key 读取公开表格
- 把行数据写入模板导出文件
