# Phase 0 研究：前端工作区与标签编辑器重构

**Feature**: `002-web-workspace-editor`
**Date**: 2026-08-21

本文记录计划阶段需要解决的技术未知项。**带实测数据的条目已在本机验证**，
仅凭推理得出的条目明确标注为「未实测」。

## R1. 二维码渲染能力

**Decision**: 使用 `bwip-js` 的 `qrcode` bcid，`eclevel` 参数承载纠错等级。

**实测结果**（本机，bwip-js 当前版本）：

| 输入 | 输出 |
|---|---|
| `bcid:'qrcode', text:'https://example.com', eclevel:'M', scale:1` | viewBox 50×50，单个 `<path>` |
| 同上，`scale:2` / `scale:3` / `scale:4` | 100×100 / 150×150 / 200×200 |
| `eclevel` 取 L / M / Q | 均为 50×50 |
| `eclevel` 取 H | **58×58**（矩阵变大） |
| `scale:3` 下全部路径坐标 | **480 个坐标，非整数 0 个** |

**Rationale**: 与既有条码走同一个库、同一种输出形式（SVG 片段），
不引入新依赖，符合宪章锁定的技术栈。坐标全整数意味着模块边缘天然落在整点上。

**Alternatives considered**: 引入专用二维码库（如 `qrcode-svg`）——被否决，
`bwip-js` 已在依赖中且已验证可用，多一个库就多一处渲染差异来源。

## R2. 二维码尺寸同样是量化的 ⚠️

**Finding**: 这是研究阶段的新发现，规格撰写时未预见。

二维码的尺寸与条码宽度遵循同一条规律：

```
二维码边长 = 模块宽度(dot) × 模块数
```

模块数由**内容长度与纠错等级共同决定**（实测：同一内容下 L/M/Q 为 50 单位，
H 为 58 单位）。因此二维码**不能自由缩放到任意尺寸**——
和条码一样只能取模块数的整数倍。

**Decision**: 二维码元素采用与条码相同的处理方式：

- 元素记录**模块宽度**（整数 dot）。
- 渲染尺寸 = 模块宽度 × 模块数，由渲染时导出。
- 拖拽缩放时吸附到可达尺寸：`floor(声明边长 / 模块数) × 模块数`。
  向下取整保证满足 FR-002（渲染尺寸不超过声明尺寸）。

**对规格的影响**: FR-037 要求二维码缩放保持宽高比——这条仍然成立（二维码本就是正方形），
但**不充分**，还须叠加量化吸附。此为实现层细节，不需要修改规格。

**已实测（2026-08-21，B3S_P + 原厂 50×30 纸）**: 模块宽度 2 / 3 / 4 dot 各打印一张，
**三张全部可读**（扫码枪与手机均可）。因此 2 dot（0.25 mm）作为二维码下限成立，
沿用与条码相同的 `MIN_MODULE_WIDTH_DOTS = 2`，无需为二维码单列下限。

> 实测中发现的量化陷阱：探针元素原为 24 mm（192 dot），而该内容的模块数为 50，
> 4×50 = 200 dot 装不下，于是按 FR-002 向下取整**静默降为 3 dot**——
> 「比较 2/3/4」的实验会打出两张完全相同的标签。
> 探针已放大到 28 mm。这条对界面同样成立：**元素框不够大时，
> 用户设定的模块宽度会被悄悄改小**，属性面板必须显示实际生效值而非请求值。

## R3. 条码模块宽度提升为元素属性

**Decision**: 将模块宽度从全局渲染选项（`IrToSvgOptions.barcodeModuleWidthDots`）
改为条码元素自身的属性。

**Rationale**: 当前实现下，同一标签上的所有条码被迫共用一个模块宽度，
且元素声明的 `widthMm` 在渲染时被完全忽略（现有注释「No scaling」）——
编辑器里拖动宽度手柄对打印结果没有任何影响。这是 FR-004 与 FR-005 的直接动因。

**迁移影响**: 既有模板中的条码没有该属性。取默认值 **2 dot**——
恰好等于现行全局默认值，因此既有模板的渲染结果不变，满足 FR-078。

## R4. 偶数模块宽度限制不成立（推翻既有实现）

**Decision**: 将 `assertEvenModuleWidth` 放宽为「整数且 ≥ 2」。

**实测结果**：7 组码制/内容 × 5 种缩放（1/2/3/5/7，含奇数）：

| 码制 | 内容 | 模块数 | s1 | s2 | s3 | s5 | s7 |
|---|---|---|---|---|---|---|---|
| code128 | ABC-12345 | 123 | ✓ | ✓ | ✓ | ✓ | ✓ |
| code128 | 1 | 46 | ✓ | ✓ | ✓ | ✓ | ✓ |
| code128 | AAAAAAAAAAAAAA | 475 | ✓ | ✓ | ✓ | ✓ | ✓ |
| code39 | ABC123 | 128 | ✓ | ✓ | ✓ | ✓ | ✓ |
| ean13 | 4006381333931 | 96 | ✓ | ✓ | ✓ | ✓ | ✓ |
| ean8 | 96385074 | 68 | ✓ | ✓ | ✓ | ✓ | ✓ |
| itf14 | 15400141288763 | 164 | ✓ | ✓ | ✓ | ✓ | ✓ |

**非整数边缘出现次数：0**

**既有实现的错误来源**: 原先的验证脚本用**第一条 path 的 `stroke-width`**
去计算所有条的边缘，而 `bwip-js` 将条按宽度分组为 4 条 path、每条各有自己的
`stroke-width`。把每条 path 与其自身的 stroke-width 配对后，奇数缩放同样整数对齐。

**下限 2 的真正依据**: 扫描规范，非渲染能力。203 dpi 下 2 dot = 0.25 mm，
是 Code 128 常用的 X 尺寸；规范下限约 0.19 mm。1 dot（0.125 mm）完全可以渲染，
只是扫不出来。

## R5. 多行文本的 SVG 表达

**Decision**: 单个 `<text>` 元素内，每行一个 `<tspan>`，
**使用绝对 `x` / `y` 而非相对 `dy`**。

**实测结果**（resvg + 打包字体，三行中英混排，字号 24，行距 28.8 = 1.2×）：

| 写法 | 渲染结果 sha256（前 16 位） |
|---|---|
| `<tspan x dy>`（相对偏移） | `62608d78b9d9f599` |
| `<tspan x y>`（绝对定位） | `62608d78b9d9f599` |
| 每行独立 `<text>` | `62608d78b9d9f599` |

**三种写法在 resvg 下逐像素完全一致。**

**Rationale**: 既然 resvg 三种都支持且结果相同，选择的依据是**浏览器一侧的稳健性**。
绝对 `x`/`y` 不依赖渲染器对 `dy` 累积语义的解释，每一行的位置都是独立算好的常量；
而保留单个 `<text>` 外壳可以让现有的 `text-anchor`（对齐方式）处理逻辑原样复用。

**行位置计算**: 第 `i` 行的基线 `y = 首行基线 + i × 1.2 × 字号`（FR-050）。
行距按 dot 网格取整，与宪章的单位约定一致。

**未实测**: 浏览器 DOM 与 resvg 在多行下的一致性。本环境无浏览器，
无法直接比对。风险已通过「绝对定位 + 显式换行（FR-049 禁止自动折行）」压到最低——
两端需要一致的只是**每一行的绘制**，而拆行是纯字符串操作，必然一致。
**建议在实现阶段补一个前后端渲染比对测试**。

## R6. 旋转后的包围盒

**Decision**: 直角旋转下，90° 与 270° 交换宽高，0° 与 180° 保持；
包围盒始终围绕元素中心计算。

```
rotation ∈ {0, 180}  →  (w, h)
rotation ∈ {90, 270} →  (h, w)
中心不变，左上角 = 中心 - (新宽/2, 新高/2)
```

**Rationale**: 锁死直角（FR-035）使这件事退化为纯粹的宽高交换，
不需要通用的旋转矩阵与外接矩形求解。

**现状缺陷**: `packages/web/src/editor/guards.ts` 的 `boundsOf()` 完全不考虑旋转。
当前没有旋转 UI 所以看不出来，一旦加上就会导致选择框错位与越界漏报（FR-036）。

## R7. 路由与标签页挂载

**Decision**: 引入 `react-router-dom`；**路由只决定"激活哪一个标签页"，
不决定"哪些标签页存在"**。标签页集合是独立的应用状态，全部保持挂载，
以样式控制显隐。

**Rationale**: FR-024 要求未激活的标签页保持编辑状态不被销毁。
路由库的默认行为是卸载未匹配的路由分支——若让它接管视图树，切走再切回时
选中元素、缩放比例、撤销历史都会丢失，直接违反 FR-012 与 FR-024。

**宪章偏离说明**: `react-router-dom` **不在宪章锁定的技术栈表中**，属于新增依赖。
理由：FR-020 – FR-023 要求可分享的深链与刷新恢复，需要地址栏与应用状态的双向同步；
自建实现需要处理 `popstate`、`pushState` 去重、基路径等细节，
而这些正是路由库已经解决的问题。使用者已明确选择 React Router。
按宪章「UI 组件规范」的同一条规则，实现时的 PR 须说明此项引入。

**Alternatives considered**: 基于 History API 自建极小路由（约 50 行）——
在本模型下技术上可行且更贴合（路由职责极少），但使用者已作决定。

## R8. 撤销与重做

**Decision**: 每个设计标签页持有一个独立的状态快照栈，
记录整个标签 IR 的不可变快照；撤销即回退指针。

**Rationale**: 标签 IR 很小（元素通常在个位数），整体快照的内存代价远低于
维护逐操作的反向补丁，且不存在"某个操作忘了写反向逻辑"这类缺陷。
FR-086 要求覆盖全部编辑操作，快照式实现天然满足——
新增一种操作不需要为它单独实现撤销。

**边界**: 栈深度上限建议 50 步；超出后丢弃最旧的。
连续拖拽应合并为一步（拖拽结束时入栈，而非每一帧），否则一次拖动会填满整个栈。

**不持久化**（FR-088）：栈随标签页存在，关闭即丢弃。

## R9. 乐观并发控制

**Decision**: 模板增加版本字段，保存时以「载入时的版本」作为前置条件；
不匹配则拒绝。

**Rationale**: FR-079 – FR-082。无认证环境下无法可靠识别锁的持有者，
悲观锁会被遗忘的标签页永久占用。

**版本字段的形式**: 使用单调递增的整数计数器，而非时间戳。
时间戳在同秒内的两次保存无法区分，而计数器不存在这个问题。

**未实测**: 无需实测，逻辑可由单元测试完整覆盖。

## R10. 偏移量数据迁移

**Decision**: 一次性迁移脚本，在应用启动时按 schema 版本号触发。

**迁移逻辑**：

1. 对每台打印机，取其**默认 Profile** 的 `offsetXMm` / `offsetYMm`，
   写入打印机新增的偏移字段。
2. 若该打印机的其他 Profile 携带**不同**的偏移值，将被丢弃的值写入日志
   （FR-077），日志需含打印机名、Profile 名与被丢弃的数值。
3. 删除 Profile 上的偏移字段。

**验证方式**（FR-078）：迁移前后各渲染一遍全部既有模板，比对逐像素哈希。
这一步可以完全离线执行，应作为迁移的自动化测试。

**回滚**: 迁移前备份数据库文件。偏移值本身可由人工重新校正，
即便迁移出错也不会造成不可恢复的损失。

## R11. 服务端文案本地化

**Decision**: 请求携带 `Accept-Language`，服务端据此选择文案资源；
CLI 通过环境变量或参数选择，共用同一份资源模块。

**Rationale**: FR-073 要求错误文案随界面语言切换。现有设计中服务端返回的是
**已措好辞的**三要素（what / why / next），前端原样显示——
这保证了同一故障不会有两套说法，且 CLI 与 Web 共用同一份文案。
把措辞移到前端会迫使 CLI 另写一份，反而制造出两套说法。

**回退规则**: 无法识别的语言标记回退到中文（项目默认语言）。

## R12. 标尺、缩放与网格吸附

**Decision**: 标尺与画布共用同一个缩放变换；刻度按当前缩放选择合适的步长
（毫米主刻度，dot 次刻度），避免高缩放比下刻度过密。

**吸附**: 拖拽过程中把指针位置换算到 dot 网格取整，再换算回 mm。
**必须基于画布的整数 dot 网格计算，不得逐元素从 mm 独立换算**——
宪章「单位约定」明确要求，否则误差会累积。

**Alt 临时脱离**（FR-033）：按下 Alt 时跳过取整步骤。

## R13. shadcn/ui 组件覆盖情况

宪章要求 UI 组件优先使用 shadcn/ui。本功能所需组件的盘点：

| 需求 | shadcn/ui 组件 | 状态 |
|---|---|---|
| 标签栏 | `tabs` | 有 |
| 右键菜单（FR-044） | `context-menu` | 有 |
| 确认对话框（FR-013、FR-056） | `alert-dialog` | 有 |
| 队列数量徽标（FR-018） | `badge` | 有 |
| 设置项开关 | `switch` | 有 |
| 缩放滑块 | `slider` | 有 |
| 图层列表滚动 | `scroll-area` | 有 |
| 提示气泡 | `tooltip` | 有 |
| 下拉菜单 | `dropdown-menu` | 有 |

自建时须复用其设计令牌（Tailwind 主题变量、`cn()`、Radix 原语），
并在 PR 中说明，符合宪章「UI 组件规范」。
