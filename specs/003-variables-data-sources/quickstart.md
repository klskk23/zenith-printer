# Quickstart：变量与表格数据源

## 环境

沿用 002 的环境，无新增系统依赖。唯一新增的 npm 依赖：

```bash
npm install @tanstack/react-table --workspace=@zenith/web
```

**不需要**安装 CSV 解析库或编码库：类型推断与规格相悖（`007` 不能变成 `7`），
编码能力 Node 自带。可以自己验证：

```bash
node -e "console.log(new TextDecoder('gbk').decode(Buffer.from([0xd6,0xd0,0xce,0xc4])))"
# 期望输出：中文
```

## 手工验收路径

### 1. 变量（US1，不需要数据源）

```
新建设计 → 属性栏定义常量 sku = ABC-123
        → 文字内容写「零件 ${sku} 号」，画布应显示「零件 ABC-123 号」
        → 二维码内容写「https://x.example/${sku}」
        → 新建序号池「测试流水」，位数 4
        → 另一段文字写「${测试流水}」
        → 打印 5 份，确认 5 张 SKU 一致、序号 0001–0005
        → 再打 3 份，确认从 0006 开始
```

**要特别试的中间状态**（FR-013/FR-016）：在文字里逐字敲 `${sku}`，从 `$` 到 `${sku}`
的每一步都不得出现错误提示，也不得中断编辑。

### 2. 数据源（US2）

准备两份 CSV 用于覆盖真实世界的坑：

```bash
# UTF-8、逗号、含前导零
printf '订单号,收件人,数量\nA-001,张三,007\nA-002,李四,42\n' > /tmp/utf8.csv

# GBK、分号（模拟中文 Excel 导出）
printf '\xb6\xa9\xb5\xa5\xba\xc5;\xca\xd5\xbc\xfe\xc8\xcb\nB-001;\xd5\xc5\xc8\xfd\n' > /tmp/gbk.csv
```

```
数据源页 → 上传 utf8.csv，命名「订单表」
        → 确认「数量」列显示 007 而不是 7
        → 上传 gbk.csv，确认中文正确、分号被识别为分隔符
        → 在表格里改一个单元格、加一行、删一行
        → 从 Google 表格或 Excel 复制一片单元格，选中某格后粘贴，确认按行列落位
```

```
设计页 → 在属性栏把设计绑定到「订单表」，文字内容写「${收件人}」
       → 打印对话框应出现行选择区，每页 10 行
       → 试三种选择：全选（按钮上应写明行数）、区间 5-12、手动勾选
       → 勾选顺序打乱，确认打印顺序仍按行号
       → 份数设为 2，确认每行连续两张、序号相同
```

### 3. 流式渲染（US3）

```
选中足够多的行使总张数接近 1000 → 提交 → 用秒表量「点击确认」到「第一张开始出纸」
```

期望 **1 秒以内**（SC-003）。改造前这个数字随批量线性增长。

### 4. 破坏性操作的确认

四处都应要求显式确认，且文案要说清后果：

| 操作 | 后果 |
|---|---|
| 打印 | 消耗耗材 |
| 重置序号池 | **可能与已贴出的标签重号** |
| 替换数据源（有列消失） | 列出会断掉引用的设计 |
| 删除数据源 | 列出正在引用它的设计 |
